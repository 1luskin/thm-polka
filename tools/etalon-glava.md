# Глава 1. Командная строка Windows: система, файлы, процессы

[плашка важности: 🔥 Обязательно — cmd есть на каждой Windows, через неё за пару минут собираешь всё для тикета]
[плашка вердикта: 🧪 Пройди Windows Command Line — в комнате своя Windows-машина, на маке её нет. ~45 мин]

## Ты на смене

22:10. Из консоли EDR (программа-охранник, которая записывает всё, что запускается на компьютерах фирмы) приходит уведомление: на файловом сервере FUE-FS01 под учёткой adm.weber за двадцать секунд подряд запустились `whoami.exe`, `systeminfo.exe` и `tasklist.exe`.

Почему это вообще стало алертом? Эти три команды отвечают на вопросы «кто я», «что это за машина» и «что тут запущено». Именно с них начинает тот, кто впервые попал на чужой компьютер, в том числе взломщик. Но ровно так же начинает и админ, который зашёл что-то починить, и программа инвентаризации. Само по себе это ни плохо, ни хорошо. Твоя работа — понять, какой из случаев перед тобой.

За пять минут надо ответить:

1. Что это за машина и кто такой adm.weber?
2. Кто запустил команды: человек в своём окне или посторонняя программа?
3. Какие процессы сейчас работают?

Всё, что ниже, — инструменты для этих ответов.

## Аналогия

Мышка и окна — это меню в кафе с картинками: удобно, пока выбираешь из нарисованного. Командная строка — разговор с поваром напрямую: «три яйца, без соли, и покажи, что в холодильнике». Картинок нет, зато просишь ровно то, что нужно, и ответ приходит сразу. На серверах меню с картинками часто нет совсем, а повар есть всегда.

## Сначала слова, без которых дальше не понять

**Командная строка** (command line, CLI — command-line interface). Окно, где компьютером управляют текстом: написал команду, нажал Enter, получил ответ текстом. На маке это Терминал.

**Оболочка** (shell). Программа внутри этого окна, которая читает набранное и выполняет. В Windows их две: старая cmd и новая PowerShell. Окно — телефонная трубка, оболочка — тот, кто отвечает на другом конце.

**Процесс и PID.** Процесс — запущенная программа. Открыл Блокнот дважды — два процесса. PID (Process ID) — номер процесса, по которому его точно находят.

**Родитель процесса.** Процесс, который запустил данный. Открыл Блокнот мышкой — его родитель `explorer.exe`, то есть рабочий стол.

Остальные слова — прямо там, где они появляются.

## Открыть cmd и понять, где ты

**На смене:** на смене у тебя может быть открыто пять окон с пятью разными машинами. Если не проверить, где ты, однажды проверишь не тот сервер и напишешь в тикет чужие данные. Поэтому первые три команды на любой машине всегда одни и те же.

**Зачем это существует.** cmd — самая старая оболочка Windows, она есть на любой версии, даже на сервере без экрана. Когда графики нет, а надо быстро что-то узнать, остаётся она.

**Как устроено.** Когда ты набираешь `hostname` и жмёшь Enter, cmd ищет программу `hostname.exe` в системной папке `C:\Windows\System32` (там лежат почти все встроенные программы Windows), запускает её и печатает ответ. Так что большинство команд — это маленькие отдельные программы, а cmd только их запускает.

**Как открыть.** На своей Windows: Win+R, набрать `cmd`, Enter. Многое системное обычному пользователю не видно, поэтому для работы открывают **от администратора**: Пуск → правой кнопкой на «Командная строка» → «Запуск от имени администратора». На немецкой Windows она называется Eingabeaufforderung.

В комнате TryHackMe Windows удалённая, и заходишь ты на неё через **SSH** — способ подключиться к командной строке другого компьютера по сети, как будто сидишь за ним. В Терминале мака:

```bash
ssh user@10.10.37.112
```

`user` — учётка, после `@` — адрес машины (комната даст свои). При первом входе SSH спросит, доверяешь ли машине: это защита от подмены сервера, отвечай `yes`. При вводе пароля символы не видны — так задумано.

**Разбор вывода:**

```
C:\Users\user>hostname
FUE-FS01

C:\Users\user>whoami
kranich\adm.weber

C:\Users\user>ver
Microsoft Windows [Version 10.0.20348.2655]
```

- `C:\Users\user>` — **приглашение** (prompt): «я готов, пиши». Заодно показывает, в какой папке ты сейчас. Всё после `>` набираешь ты.
- `hostname` — имя машины. Сверяешь с алертом: FUE-FS01 совпадает, ты на нужной машине.
- `whoami` — под кем ты работаешь, в виде «домен\имя». **Домен** — общая система учёток фирмы: один логин подходит ко всем её компьютерам. `kranich` — домен фирмы, `adm.weber` — учётка. Если вместо домена стоит имя самой машины (`fue-fs01\admin`), это **локальная учётка**: она есть только на этом компьютере. Приставка `adm.` в фирмах обычно значит административную учётку, с повышенными правами.
- `ver` — версия Windows. Главное в ней — **номер сборки** (build), здесь 20348. По нему версию определяют точнее, чем по названию: 20348 — Windows Server 2022, 22631 — Windows 11 23H2, 19045 — Windows 10 22H2.

**Ещё пригодится:** `cls` очищает экран, Ctrl+C останавливает зависшую команду, `команда /?` показывает справку (`dir /?`), `help` — список команд cmd.

**Варианты, которые встретятся:** после SSH приглашение может начинаться с `PS` — значит, ты в PowerShell, а не в cmd. Набери `cmd`.

**Если не получилось:**
- `'hostnme' is not recognized as an internal or external command` — опечатка, такой команды нет.
- `Access is denied` (нем. Zugriff verweigert) — ничего не сломалось, не хватает прав. Перезапусти cmd от администратора.

**Ошибка новичка:** открыть cmd без прав администратора и решить, что команда «не работает». Ошибаются, потому что окно выглядит одинаково — права видно только в заголовке («Administrator:»).

## Переменные окружения: set

**На смене:** по переменным видно, кто ты и что за машина, а главное — где Windows ищет программы. Это место атакующие подменяют, чтобы вместо настоящей программы запускалась их.

**Зачем это существует.** Любой программе при запуске нужно знать базовые вещи: кто пользователь, где его папка, куда класть временные файлы, где искать другие программы. Чтобы каждая не выясняла это сама, Windows заранее раздаёт всем один и тот же набор подписанных значений. Это и есть **переменные окружения** (environment variables): у каждой есть имя и значение, например `USERNAME=adm.weber`. Похоже на стикеры на холодильнике, которые читает каждый в доме.

**Откуда они берутся.** Часть задаёт сама Windows для всей машины, например `COMPUTERNAME`. Часть привязана к пользователю: `USERNAME`, `USERPROFILE`. Ещё часть дописывают программы при установке: поставил Python — его папка появилась в `Path`. Хранится всё это в **реестре** (большой базе настроек Windows), и каждая запущенная программа получает свою копию.

**Как посмотреть.** `set` без ничего выводит весь список, обычно строк тридцать-сорок. `set USER` — только переменные, имя которых начинается на USER. Регистр не важен: `set path` = `set Path`. Чтобы подставить значение в команду, имя берут в проценты: `echo %USERNAME%` напечатает учётку, а `cd %TEMP%` перенесёт в папку временных файлов на любой машине, как бы там ни звали пользователя.

**Разбор вывода:**

```
C:\Users\adm.weber>set
COMPUTERNAME=FUE-FS01
USERDOMAIN=KRANICH
USERNAME=adm.weber
USERPROFILE=C:\Users\adm.weber
TEMP=C:\Users\adm.weber\AppData\Local\Temp
Path=C:\Windows\system32;C:\Windows;C:\Windows\System32\Wbem
```

- `COMPUTERNAME` — имя машины, то же, что `hostname`.
- `USERDOMAIN` и `USERNAME` — домен и учётка, то же, что `whoami`.
- `USERPROFILE` — личная папка пользователя: рабочий стол, загрузки, документы.
- `TEMP` — папка временных файлов. Писать туда может любая программа без прав администратора, поэтому сюда часто падает скачанное и подозрительное.
- `Path` — самая важная. Список папок через точку с запятой. Когда пишешь просто `whoami`, без полного пути, Windows ищет `whoami.exe` по этим папкам слева направо и запускает **первый найденный**.

**Норма и подозрительное.** Раз берётся первое совпадение, можно подсунуть в начало `Path` папку вроде Temp и положить туда поддельный `net.exe`. Админ пишет `net` — запускается подделка, и он ничего не замечает. В MITRE (справочник приёмов атак, по нему в SOC называют, что происходит) это T1574.007. Норма: `Path` начинается с `C:\Windows\system32`, папки пользователей и Temp — в конце или их нет вовсе.

```
Норма:      Path=C:\Windows\system32;C:\Windows;...
Подозрение: Path=C:\Users\Public\tools;C:\Windows\system32;...
```

**Попробуй сам.** На маке то же самое: в Терминале `echo $PATH` (на маке переменную пишут через `$`, разделитель — двоеточие) и `env` — аналог `set`. Посмотри, какая папка у тебя стоит первой.

**Если не получилось:** `set Patth` просто ничего не выведет, без ошибки. Проверь, как написано имя.

**Ошибка новичка 1:** проверять только, что System32 в `Path` есть. Опасна лишняя папка, которая стоит **перед** ней.

**Ошибка новичка 2:** думать, что `set` меняет что-то навсегда. `set X=1` живёт только в этом окне: закрыл — значения нет. Навсегда записывает `setx`. Если `setx` с изменением `Path` попался в алерте — это стоит проверить.

## Что за машина: systeminfo

**На смене:** в тикет идёт точная система и уровень обновлений. По ним L2 сразу понимает, может ли машина быть уязвима к известной атаке.

**Зачем это существует.** Админу нужен «паспорт машины» одной командой, без кликов по десятку окон настроек. **Уязвимость** — дыра в программе, через которую можно взломать; производитель закрывает её обновлением. Поэтому машина без свежих обновлений — первый кандидат на взлом, и это видно как раз в паспорте.

**Как устроено.** `systeminfo` опрашивает саму Windows: версию, сетевые карты, установленные обновления, время загрузки — и печатает около шестидесяти строк. Опрашивает всё по очереди, поэтому на удалённой машине отвечает иногда 10–20 секунд.

**Разбор вывода** (только нужные строки):

```
Host Name:          FUE-FS01
OS Name:            Microsoft Windows Server 2022 Standard
OS Version:         10.0.20348 N/A Build 20348
System Boot Time:   15.09.2026, 06:14:52
Domain:             kranich.local
Hotfix(s):          42 Hotfix(s) Installed.
```

- `OS Name`, `OS Version` — система и номер сборки. Server — это сервер, а не рабочий компьютер сотрудника. На сервере обычно никто не сидит, поэтому «ручные» команды там заметнее.
- `System Boot Time` — когда машину последний раз включали. Месяцы назад — обновления, которым нужна перезагрузка, не ставились. Перезагрузка прямо во время инцидента — записать.
- `Domain` — в каком домене машина. `kranich.local` — домен фирмы. `WORKGROUP` — ни в каком домене, живёт сама по себе; для сервера фирмы это странно.
- `Hotfix(s)` — сколько **исправлений** (hotfix — небольшое обновление-заплатка) стоит. 42 на сервере — нормально, 0–3 — машина почти не обновлялась.

**Длинный вывод:** `systeminfo | more` листает постранично (пробел — дальше, `q` — выход). Палка `|` — **конвейер**: передаёт вывод одной команды на вход другой; здесь `more` просто режет текст на страницы.

**driverquery** работает так же, но показывает **драйверы** — маленькие программы, через которые Windows управляет устройствами (видеокарта, сеть, диск). Драйвер работает с самыми высокими правами, поэтому вредоносный драйвер очень опасен. L1 обычно сверяет список с тем, что пришло в алерте.

**Если не получилось:** долго нет ответа — подожди до 20 секунд, команда не зависла. `Access is denied` на чужой машине — нужны права администратора.

**Ошибка новичка 1:** писать в тикет «Windows 10» по памяти. Копируй `OS Version` как есть: 10.0.20348 — это Server 2022, а не «десятка». Путают, потому что у всех современных Windows номер начинается с 10.0.

**Ошибка новичка 2:** вставлять в тикет все 60 строк. L2 нужны пять: имя, система со сборкой, время загрузки, домен, число обновлений.

**В тикет:**

```
FUE-FS01: Windows Server 2022 (Build 20348), домен kranich.local,
загружен 15.09.2026 06:14, 42 hotfix.
```

## Норма процесса: путь и родитель

**На смене:** главный приём главы. По имени процесса ничего нельзя сказать: подделку называют так же, как настоящую программу. Решает связка «имя + путь + родитель».

**Зачем это существует.** Каждая программа в Windows запускается другой программой — так система следит, кто что породил, и может закрыть всё «семейство» разом. Из-за этого у системных программ есть постоянный порядок запуска: одни и те же родители, одни и те же папки. Нарушение этого порядка — самый частый след чужой программы.

**Как устроено.** Когда процесс запускает другой, Windows записывает новому номер родителя (Parent PID). Получается дерево:

[визуальный блок: нормальное дерево Windows]

```
System (PID 4)            ядро — главная программа Windows
└─ smss.exe               запускает сеанс
   └─ wininit.exe
      └─ services.exe     запускает все службы
         └─ svchost.exe   «общий дом» для служб, их всегда несколько
   └─ winlogon.exe        вход пользователя
      └─ explorer.exe     рабочий стол — родитель твоих обычных программ
         └─ cmd.exe       ты открыл сам
```

**Служба** (service) — программа, которая работает в фоне без окна и стартует вместе с Windows: печать, обновления, общие папки. Все службы запускает `services.exe`, а живут они внутри `svchost.exe`.

**Как посмотреть.** `tasklist` показывает только имя и PID — ни пути, ни родителя. В cmd родителя показывает `wmic` (старый инструмент; на новых Windows 11 его может не быть, тогда смотрят в Sysmon или EDR):

```
C:\>wmic process where "name='cmd.exe'" get ExecutablePath,ParentProcessId,ProcessId
ExecutablePath               ParentProcessId  ProcessId
C:\Windows\system32\cmd.exe  3120             5844

C:\>wmic process where "processid=3120" get ExecutablePath,Name
ExecutablePath           Name
C:\Windows\explorer.exe  explorer.exe
```

**Разбор вывода:**
- `ExecutablePath` — откуда запущен файл. Для cmd норма — `C:\Windows\system32`.
- `ParentProcessId` — номер родителя, здесь 3120.
- `ProcessId` — номер самого процесса, 5844.
- Вторая команда ищет процесс с номером 3120: это `explorer.exe`, то есть cmd открыли мышкой с рабочего стола. Норма.

**Норма и подозрительное:**

| Что видишь | Норма | Подозрительно |
|---|---|---|
| родитель `svchost.exe` | `services.exe` | `winword.exe`, `cmd.exe` — почти наверняка маскировка |
| путь системной программы | `C:\Windows\System32` (или `SysWOW64`) | `C:\Users\Public\svchost.exe` — чужая под чужим именем |
| родитель `cmd.exe` или `powershell.exe` | `explorer.exe` (человек открыл сам) | `winword.exe`, `excel.exe` — документ с макросом запустил оболочку; служба веб-сервера — взломанный сайт |

**Если не получилось:** `No Instance(s) Available.` — процесса с таким именем или номером нет; это ответ, а не ошибка. Родитель уже закрылся — его номера в списке не будет, тогда родителя смотрят в журнале Sysmon (событие 1) или EDR.

**Ошибка новичка:** успокоиться на знакомом имени — «это svchost, он системный». Ошибаются, потому что имя видно сразу, а путь и родителя надо искать отдельно.

**В тикет:**

```
FUE-FS01: cmd.exe (PID 5844) из C:\Windows\system32, родитель explorer.exe (PID 3120) —
запущен пользователем вручную.
```

## Сделай сам

1. В Терминале мака: `whoami`, `hostname`, `echo $PATH`. Найди свою домашнюю папку в `env`.
2. В комнате: `systeminfo` и выпиши пять строк для тикета.
3. Найди родителя своего `cmd.exe` через `wmic` и запиши его по формату «В тикет».
